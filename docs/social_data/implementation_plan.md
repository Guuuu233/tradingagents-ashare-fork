> **修订：** 2026-08-27（时间语义第二轮）。本文件是社交轨**唯一详细实施方案**。跨轨合入顺序由当前任务系统维护，不属于本规范。不要另建平行社交方案，也不要按更早的 Task 1–15 派发。
>
> **For agentic workers:** 按本文件任务顺序实施。每个任务先写可失败测试，再做最小实现。禁止 `_v2` / `_new` / `_fixed` 并行路径。Gate 0–3 的 `legacy_proxy` 是已批准的一次性迁移例外，只能存在于单一配置门控适配层。
>
> **已废弃、禁止再实现的映射：** `content_observed_at = add_ts`、`metric_observed_at = last_modify_ts` 当作平台正文/互动时间。`add_ts` 与 `last_modify_ts` 只是 MediaCrawler 工作库的库务时间。

**Goal:** 在不破坏现有 provider 路由、DataCollector 并发缓存、防前视、双时间窗、报告持久化和用户模型配置的前提下，把小红书、抖音公开帖子与评论接成真实、可追溯、可回滚的社交舆情数据源。

**Architecture:** MediaCrawler 作为独立采集进程，对其工作库做 **update-in-place**。导入器把每一版工作行转换成 TradingAgents **append-only** social archive 快照。分析链只读 archive：`SocialDataProvider` → `DataCollector`（市场 `_fetch_all` 之后、独立短超时）→ `social_data_context` → prompt。不把 MediaCrawler 塞进 `BaseMarketDataProvider`。不在分析请求期间启动爬虫。不新增一个实际上不会被调用的 social LangChain tool。不继承 MediaCrawler 的原地更新语义。

**Tech Stack:** TradingAgents-AShare Python 3.10、标准库 `sqlite3/dataclasses/zoneinfo/hashlib`、现有 LangGraph/LangChain/FastAPI/SQLAlchemy/pytest；MediaCrawler 独立 Python 3.11 + uv + Chrome/CDP；工作库与 archive 本地 MVP 均为 SQLite。

**Spec:** 本文件；长期契约与运维手册落在 `docs/social_data/`（仓库已有 `docs/`，不是新顶层目录）。

## 一、结论先行

### 1. 主路径（唯一）

```text
小红书 / 抖音
      │
      ▼
MediaCrawler 独立进程（强制 sqlite；工作库 update-in-place）
      │
      ▼
MediaCrawler 工作库（可变，禁止分析链直接当历史库）
      │ 导入：只读源表 → append-only snapshot
      ▼
TradingAgents social archive（不可变、只追加）
      │ 只读；源时间判断正文；snapshot_at 判断指标
      ▼
SocialDataProvider
      │
      ▼
DataCollector.collect()
  1) 现有 _fetch_all 市场并行采集
  2) 之后独立短超时读取 social archive
      │
      ▼
social_data_context + market_data_context.market_attention
      │
      ├─ social_media_analyst prompt
      ├─ AgentState / Propagator / api/main.py 三处 init
      ├─ research_manager / evidence_verifier / report_quality_gate
```

禁止：分析链上启动爬虫；新增 `get_social_sentiment_bundle` 之类不会被 bind 的 tool；把社交任务丢进 `_fetch_all` 的市场线程池；对 `social_record_snapshots` 做 UPDATE/DELETE。

1. `tradingagents/dataflows/social/`：独立契约、archive、importer、registry、只读 provider、聚合器、collector。
2. `DataCollector.collect()`：在 `_fetch_all` **返回之后**写入 `social_data_context`，独立超时；失败不得让市场任务失败或占满 `FETCH_MAX_WORKERS`。

### 3. 时间字段分层（绑定）

三类时间不得混用：

| 层 | 字段 | 来源 | 用途 | 禁止 |
|---|---|---|---|---|
| 平台源时间 | `published_at` | XHS 帖 `time`；XHS 评 / DY 帖评 `create_time` | 内容何时发布 | 用 `add_ts` / `last_modify_ts` 冒充 |
| 平台源时间 | `source_updated_at` | XHS 帖 `last_update_time`；其余表无此列则为 null | 仅存储；**可靠性单独验证通过前不参与资格** | 未验证就当正文观察时间 |
| 爬虫库务 | `first_seen_at` | 源表 `add_ts` | 该对象被 MediaCrawler **首次写入**工作库的时间 | 解释为平台发布时间或正文编辑时间 |
| 爬虫库务 | `snapshot_at` | 源表 `last_modify_ts` | 该工作行这一版被爬虫 **最后写入**的时间；指标资格用它 | 解释为平台互动发生时间或正文时间 |
| 归档审计 | `ingest_at` | 导入器时钟 | 只证明何时写入 TradingAgents archive | 参与任何资格判断；回填缺失源时间 |

钉住 SHA `d6f7c5bb906b6dac40ddf343ef9e26438a3de092` 的代码依据：

- 官方注释：`last_modify_ts` *Generated by MediaCrawler, mainly used to record the latest update time of a record in DB storage*。
- XHS `add_content` 写入 `add_ts = get_current_timestamp()`；`update_content` 只改 `last_modify_ts`、互动数字段和 `last_update_time`，**不改** `title`/`desc`。
- DY `store_content` 对已存在行 `setattr` 逐字段覆盖，包括 `desc` 与互动数；`add_ts` 只在首次插入时写入。
- XHS / DY 评论表均无 `last_update_time`。

因此：历史重建只能依赖 TradingAgents 自己的 append-only 快照，不能回放 MediaCrawler 当前工作行。

## 三、设计规格

### 3.1 组件职责

#### MediaCrawler

- 外置进程；保管 Cookie、CDP、登录态。
- 工作库必须是 SQLite。启动前校验实际 save option；不是 sqlite 则非零退出，禁止 JSONL 空转。
- 控制 API 只监听 `127.0.0.1`。登录使用 cookie，不把扫码流程接进分析链。
- 工作库允许原地更新；TradingAgents **不得**把该库当历史事实源。

#### `MediaCrawlerImporter`

- 只读源表，不改源表。
- 表/列 fingerprint 白名单；不认识则 `failed/schema_mismatch`。
- 映射到 `SocialRawRecordV1`；空正文允许归档。
- 必要时间字段缺失或非法则拒收该行。
- **只 INSERT** 新 snapshot；相同 `(record_id, content_hash, metrics_hash)` 则 `rows_inserted=0`。禁止 `UPDATE`/`DELETE` `social_record_snapshots`。

#### `ArchiveSocialDataProvider`

- 只读 URI + `PRAGMA query_only=ON` + `busy_timeout` 与社交短超时一致。
- 按 5.2 做资格判断；返回 typed status。
- 不做 LLM，不回退新闻，不打开 MediaCrawler 工作库。

#### `SocialSentimentAggregator`

- 去重、采样、词典分类、确定性聚合。
- 空正文：可计入注意力，不得计入方向性情绪。
- 正文可用而指标不可用：基础权重，不用互动数。
- 低覆盖：score=`null`，label=`insufficient`，`direction_allowed=false`。

#### 迁移适配层（Gate 0–3 唯一 if）

单一函数，例如 `resolve_social_analyst_inputs(mode, social_data_context, pool)`：

- `disabled`（Gate 4 前）：返回现有 news/zt_pool/hot_stocks，trace `source_mode=legacy_proxy`。
- `shadow`：照常构建并持久化 bundle，但分析师输入仍走 legacy 字段；bundle 不得进入总监方向证据。
- `active`：只返回 bundle + market_attention；不可用时明确缺口，不回退新闻。

Gate 4 删除该函数中的 legacy 分支和旧 prompt 新闻措辞。

#### `social_media_analyst`

- active：只解释 `sentiment_bundle` 与市场关注度。
- 四段：数据状态、社交观点、社交热度、市场关注度。

### 3.2 MediaCrawler 钉住契约

钉住 SHA `d6f7c5bb906b6dac40ddf343ef9e26438a3de092`。

- 表：`xhs_note` / `xhs_note_comment` / `douyin_aweme` / `douyin_aweme_comment`
- 许可：Non-Commercial Learning License 1.1
- Python：`requires-python >=3.11`
- 控制 API：`/crawler/start|stop|status|logs`，不是查询 API
- `CrawlerStartRequest.save_option` 默认 `jsonl`，Enum 含 `sqlite`；实施必须显式 `sqlite` 并回读校验
- `ENABLE_CDP_MODE=True`；默认 `login_type=qrcode` 不能用于无人值守，导入工作流使用 cookie

### 3.3 源表映射（钉住 SHA，不得猜测）

秒/毫秒：绝对值 `>= 10^12` 按毫秒，否则按秒。非法、负数、超出合理年份、字面 `0` 当作缺失。

| 平台 | 内容表 | `published_at` | `source_updated_at` | `first_seen_at` | `snapshot_at` |
|---|---|---|---|---|---|
| 小红书帖 | `xhs_note` | `time` | `last_update_time`（未验证前不参与资格） | `add_ts` | `last_modify_ts` |
| 小红书评 | `xhs_note_comment` | `create_time` | null（无此列） | `add_ts` | `last_modify_ts` |
| 抖音帖 | `douyin_aweme` | `create_time` | null（无此列） | `add_ts` | `last_modify_ts` |
| 抖音评 | `douyin_aweme_comment` | `create_time` | null（无此列） | `add_ts` | `last_modify_ts` |

`ingest_at` 一律为本次导入时钟（UTC），**不参与**历史资格。

必要字段（缺一拒收）：`published_at`、`first_seen_at`、`snapshot_at`。`source_updated_at` 在验证完成前缺失不拒收。禁止用 `ingest_at` 或 `now()` 回填上述任一字段。

互动数字段：xhs liked/collected/comment/share；dy liked/comment/share/collected。源列为 Text，默认 `"0"` 无法区分未知与真零：空串/非法 → `null`；字面 `"0"` 记 0，run 计数 `zero_or_unknown_ambiguous`。禁止把缺失填 0 当成真实零互动后用于方向权重。

### 3.4 `last_update_time` 单独验证（Gate 1 交付物，不是资格默认）

钉住 SHA 下 `update_xhs_note` 把平台 `last_update_time` 写入工作行，但 `update_content` **并不更新** `title`/`desc`。因此该字段**不能默认等于「当前归档正文的编辑时间」**。

Gate 1 必须产出 `docs/social_data/xhs_last_update_time_verification.md`，至少回答：

1. 真实或夹具重抓后，`last_update_time` 是否在仅互动数变化时也变动。
2. 平台改文案时，工作行 `desc` 是否同步变化。
3. `last_update_time == 0` / 缺失 / 早于 `time` / 晚于 `last_modify_ts` 的频率。
4. 结论只能是：`untrusted`（保持存储、不参与资格）或 `trusted_as_content_update`（此后才允许把 `source_updated_at <= cutoff` 加入正文资格）。未写出该结论前，资格代码必须忽略 `source_updated_at`。

规则：

- 未知数字必须是 `null`，不能写 `0` 冒充已知。
- `text` 允许空字符串；空正文只可贡献注意力，不能贡献方向。
- URL 去追踪参数；不得保存 Cookie、token、手机号、昵称、下载链接。
- `author_id_hash` 只接受已脱敏 creator hash；缺失为 `null`。
- 评论必须带 `root_post_record_id`；二级评论再带 `parent_record_id`。
- `record_id` 稳定标识对象；`snapshot_id` 标识这一版正文+指标。
- 必要时间字段缺失或非法：拒收，计入 `rows_rejected`，不得回填 `ingest_at` 或 `now()`。
- `source_updated_at` 允许 null；不得用 `snapshot_at` 或 `first_seen_at` 填它。

## 五、聚合数据契约 `SentimentBundleV1`

```json
{
  "schema_version": "social.sentiment_bundle.v1",
  "status": "available",
  "requested_as_of": "2026-08-26",
  "cutoff_at": "2026-08-26T15:59:59Z",
  "content_as_of": "2026-08-26T03:12:11Z",
  "metric_as_of": "2026-08-26T06:10:00Z",
  "direction_allowed": true,
  "reason_codes": []
}
```

`content_as_of` = 本 bundle 所用正文快照的最大 `published_at`（源时间）。`metric_as_of` = 所用指标快照的最大 `snapshot_at`。二者都可以为 null（无合格正文 / 无合格指标）。**不要**把 `ingest_at` 写进这两个字段。

所有时间比较必须先转 timezone-aware datetime，禁止字符串比较。历史日 cutoff = 上海时区该日 `23:59:59.999999`，序列化为等价 UTC。当前日 cutoff = 实际 `now_cn()`，不得预设到当天结束。未来日或非法日期：`refused`。

### 5.1 状态语义

| status | 定义 | `direction_allowed` |
|---|---|---|
| `available` | 帖子/已分类/作者均达最低阈值，可计算方向分数 | true |
| `partial` | 有真实记录，但平台、时间窗或分类覆盖不完整 | false（除非明确达到方向阈值且双平台规则满足；默认 false，见 5.4） |
| `empty` | 对请求平台和窗口有成功采集覆盖，但确认没有匹配记录 | false |
| `refused` | 非法/未来日期，或没有任何记录能证明正文资格 | false |
| `failed` | archive 缺失、schema 不兼容、读取异常 | false |
| `timeout` | archive 锁等待超过社交短超时 | false |
| `not_applicable` | 功能关闭、非 A 股、未选择 social analyst | false |

`empty/refused/failed/timeout/not_applicable` 以及 label=`insufficient` 的 `social_sentiment.score` 一律 `null`，label 一律 `insufficient`。不能写 `0.0/neutral`。

单平台有数据：status 至少 `partial`。`partial` 默认 `direction_allowed=false`。

### 5.2 正文与指标资格（分别判断）

历史查询 **只扫描 archive 快照**，不读 MediaCrawler 工作库。

同一 `record_id` 先在 archive 中选出 `snapshot_at <= cutoff` 的快照，取 `snapshot_at` 最大的一条作为候选观测。没有这样的快照则该对象没有历史观测。

正文进入内容池，当且仅当候选观测存在，并且：

```text
window_start <= published_at <= analysis_cutoff
first_seen_at <= analysis_cutoff
entity mention 命中目标 symbol
```

在 `xhs_last_update_time_trusted=true` 之后，XHS 帖子额外要求 `source_updated_at` 为 null 或 `<= cutoff`。验证完成前 **不得**加这一条。

互动指标进入权重，当且仅当该记录已进入内容池，并且：

```text
snapshot_at <= analysis_cutoff
```

（候选观测的定义已经蕴含这一条；若实现走「正文来自更早快照、指标来自较新快照」的拆分，指标快照仍必须 `snapshot_at <= cutoff`。）

- 正文可用、指标不可用：保留正文，互动权重固定 1.0，metrics 视为未知，不推进 `metric_as_of`。
- 正文不可用：整条排除，计入 `observed_after_cutoff_excluded` 或 `no_historical_snapshot`。
- `ingest_at` 不参与上述任何比较。回归必须覆盖：`snapshot_at` 与源时间均 ≤ cutoff、`ingest_at` > cutoff → **仍应计入**。
- 后补抓取：`published_at` 早但 `first_seen_at` 晚于 cutoff → 排除。
- 互动后更新：cutoff 之后的新 snapshot 不得把最新 likes 带进历史日；只用 `snapshot_at <= cutoff` 的那一版。
- 抖音无独立源更新时间，且工作库会覆盖 `desc`：历史正文只能来自 archive 中 `snapshot_at <= cutoff` 的快照，不能从「当前工作行」回推。
- 每次 historical test 冻结 `now_cn()`。

### 5.3 实体映射

完整代码 1.00、标准名 1.00、唯一别名 0.95、专属关键词无冲突 0.90。行业/概念词只打 topic，不绑个股。多股票同文分别映射。全角/半角 NFKC。

### 5.4 确定性采样和情绪算法

第一版词典 `cn_equity_stance_lexicon.v1`，不改用户 LLM 绑定。

1. 文本 hash 去重；重复组最多一份权重。
2. 每位作者最多 5 条。
3. 先近期帖子，再热评/最新评论；默认上限 100 帖 / 300 评。
4. 帖子基础权重 1.5，评论 1.0；**空正文权重 0（方向）**，仍可计入 `social_attention` 的 post/comment count。
5. 时间衰减半衰期 3.5 天（按 `published_at`，不是 `snapshot_at`）。
6. 只有指标合格的 likes 可增加互动权重，系数最大 1.5。
7. 两平台都有数据时单平台最终权重最多 65%；只有一平台则 status 至少 `partial` 且 `direction_allowed=false`。
8. 否定词在情绪词前 3 个汉字内翻转极性；无法识别记 `unknown`，不当 neutral。
9. 排序稳定 tie-breaker：`record_id`。

最低可判定阈值：帖子 ≥3、已分类 ≥20、不同作者 ≥10。未达则 score=null、label=insufficient、`direction_allowed=false`。

方向规则 bullish/bearish/mixed/neutral/insufficient。`is_calibrated_probability=false`。

### 5.5 bundle status → ledger / data_gaps 映射

`merge_data_gaps` 只合并 ledger status ∈ `{failed, timeout, unavailable, refused, error}`。社交侧必须按下表写入 `social_data_context.data_failure_ledger`，禁止把 empty/insufficient 写成 failed。

| 来源状态 | ledger.status | reason_code | gap_class | 进入 merge_data_gaps | 禁止 |
|---|---|---|---|---|---|
| available | 不写失败条目 | — | — | 否 | 把分数写成概率 |
| partial / insufficient 覆盖 | 不写失败条目 | `social_insufficient_coverage` 或 `social_platform_partial` 留在 bundle.reason_codes | — | 否 | 伪装成 failed 或 0.0/neutral |
| empty | 不写失败条目 | `social_empty` 在 reason_codes | — | 否 | 伪装成 failed 或“无风险” |
| not_applicable | 不写失败条目 | `social_not_applicable` | — | 否 | 回退新闻 |
| refused（非法/未来日） | `refused` | `social_invalid_as_of` / `social_future_as_of` | structural | 是 | 回退今天 |
| refused（无历史正文快照） | `refused` | `social_no_historical_snapshot` | structural | 是 | 用后补帖子或当前工作行 |
| archive 缺失 / schema | `failed` | `social_archive_missing` / `social_schema_mismatch` | operational | 是 | 空字符串继续分析 |
| 锁等待超时 | `timeout` | `social_archive_locked` | operational | 是 | 无限等待或占用市场线程池 |

`source` 字段使用 `social_archive` 或 `social.<platform>`。`gap` 文本必须是 `【数据获取失败】...` 仅当 ledger.status 为上表“进入=是”的行。empty/insufficient 的用户可见说明写在 bundle 与报告正文“社交方向不可判断”，不走失败模板。

## 十、迁移和回滚（Gate 0–4）与真实验收清单

- 清空 canary；保留 mode 开关。
- 独立提交删除 `legacy_proxy` 分支、适配层 legacy 臂、旧 social prompt 新闻措辞。
- `disabled` 只表示社交不可用（`not_applicable`），不再自动拿新闻替代。
- **D-009 铁律：未逐级通过 Gate 0–3 前，绝对不得宣称社交接入完成。DAV-545 只证明 Gate 4 独立删除项在代码层面已提前合入，绝不代表真实业务验收通过。**

## 十三、主要风险

1. 许可：非商业学习；对外收费必须停开源爬虫。
2. 平台风控：低频、小名单、cookie、串行；分析链不处理验证码。
3. 历史数据从启用日起向前积累；此前报告只能 `social_no_historical_snapshot`。
4. 词典分数不是预测概率。
5. 源表漂移：fingerprint + 钉住 commit。
6. 脏工作树污染提交：pathspec 白名单；另一窗口的数据/裁决改动稍后合入，不要抢。
7. `last_update_time` 与归档正文可能不一致（XHS update 不写 desc）。未验证当内容时间会制造假资格或假缺口。

## 十五、最终边界

MediaCrawler 不是 TradingAgents 的在线工具，而是外置、可原地更新的采集器。内部接入的是 append-only 社交证据 archive：平台源时间判断发布，`add_ts` 只证明首次发现，`last_modify_ts` 只作为 `snapshot_at` 约束指标，`ingest_at` 只做运行审计。新闻、榜单热度、社交观点不再混成一个舆情近似值。`legacy_proxy` 只活到 Gate 4 的独立删除提交为止。
