# B1 输出契约 v1：行业相对概率与价位方向（2026-10-02，总控，D-066 B1/B3）

依据：D-066（出口标准 B1–B3）、D-046 第 3 项、DAV-1226、F1 协议 v1.0.1 §4.3/§4.4/§5.3/§5.4/§10、D-037（生成侧改动单独放行）。

## 0. 实测现状（生产库只读备份，299 份 09-25 起完成的双档，固定账户）

| 项 | 实测 |
|---|---|
| 档位动作分布 | WAIT 274、NO_TRADE 214、HOLD 34、SELL 29、BUY 13（另 34 档未完成） |
| 现有 `probability` 覆盖 | BUY 2/13、SELL 9/29、HOLD 1/34；可执行档合计 11/42 ≈ 26% |
| 现有 `probability` 刻度 | 只出现 0.32/0.35/0.45/0.58/0.62 等少数几个值，刻度粗 |
| BUY 价位 | 13/13 同时有目标与止损，全部止损 < 目标 |
| SELL 价位 | 19 档两者齐全，6 档缺目标，4 档两者都缺。齐全的 19 档里 13 档"止损 ≥ 目标"（空头式），6 档"止损 < 目标"（多头式，如 601127 中线 43.61/50.09、300274 中线 80/85.2） |

结论：
1. 现有 `probability` 的含义是"主周期期末价格高于基准价的绝对上涨概率"，不是 F1 需要的"T+10 行业相对概率"。而且它由事后的"结构化提取"模型调用或正则兜底产出，不是单一决策节点的直接输出，不满足 §4.4。
2. SELL 的价位方向没有约定：同一个字段名，有约 1/3 的档按多头理解，2/3 按空头理解。
3. 现有提示词都没有说明"只做多、不融券"。

## 1. 新字段：`p_rel_t10`（行业相对概率）

- **语义**：P(本股从分析日收盘起 T+10 个交易日的收益 − 所属申万一级行业指数同期收益 > 0 | 截止分析日的合法信息)。
- **行业基准**：申万 2021 版一级行业指数，成分按分析日时点确定（`in_date ≤ 分析日`，且 `out_date` 为空或晚于分析日）。2026-10-02 零模型探针确认，项目现用的 Tushare 网关可取到以下三类数据，因此基准可得：
  - `index_classify`：L1 共 31 个行业；
  - `index_member_all`：含 in/out 日期；
  - `sw_daily`：日收盘。
- **刻度**：整数百分点，取值 1–99。0 和 100 代表确定性断言，按无效处理。
- **产出节点（§4.4 单一决策节点，事先固定）**：研究经理。实测每份双档的短线、中线两档各自独立运行辩论与研究经理（`llm_call_logs` 中 `Research Manager` 分别带 short/medium 两种 horizon）。因此在 `MANAGER_VERDICT` 机读块中新增键 `"p_rel_t10": <整数>`，两档都必须给出。
  - **主值**：取短线档。T+10 与短线周期一致，F1 记录以它为准。
  - **中线档的值**：只作一致性监测（两档差值分布），不进入 F1 主记录。
- **与现有 `probability` 的关系**：现有字段保持原样，不改语义、不删除，因为 `calibration_service` 用它做 T+10/T+40 绝对价格校准。两者并存。研究员提示词里"上涨概率"的定义不改。
- **与门控的关系**：无论档位最终是 BUY/SELL/HOLD/WAIT/NO_TRADE/ABSTAIN，`p_rel_t10` 一律保留，并标注为"预测，非交易信号"。现有的"不可执行档把目标、止损、置信度置空"规则不适用于它。
- **行业名注入**：研究经理提示词中加一行"行业基准：申万一级 <行业名>（<指数代码>）"，数据来自上面的时点成分。取数失败时这一行写"行业基准：获取失败"，并记入 `data_gaps`；预测仍须给出，不因此跳过。只注入行业名，不向模型提供行业指数行情，v1 不扩输入。

### 1.1 解析与无效判定（确定性，零模型）

只从该档最终采纳的 `MANAGER_VERDICT` 块读取。**禁止**用"结构化提取"模型调用或正则从正文兜底补值。

| 状态 | 判定 |
|---|---|
| `valid` | 键存在，值为整数（或小数部分为 0 的数字），1 ≤ 值 ≤ 99 |
| `missing` | 机读块不存在或解析失败，或键不存在，或值为 null |
| `malformed` | 值不是数字（含字符串 "60%"），或带非零小数，或超出 1–99 |
| `node_failed` | 研究经理未运行，例如前置守卫已阻断全部模型调用、档位失败 |

- **不做格式重试**：拿到无效值就记为无效，不为补齐该字段重新调用模型。传输层重试（429、超时）照旧，与本规则无关。
- **返修与输出**：研究经理若经"返修"重写，以最终被采纳的那一版为准。
- **落库**：每档 `forecast = {"contract": "b1.v1", "p_rel_t10": int|null, "status": ..., "benchmark": {"src": "SW2021", "level": "L1", "code": ..., "name": ...}|null, "node": "research_manager"}`。

## 2. 价位方向契约（只做多语境）

本系统服务的账户只做多，不融券。各动作含义与价位规则如下：

| 动作 | 含义 | 必填价位 | 方向规则（ref = 分析日前复权收盘） |
|---|---|---|---|
| BUY | 新开仓或加仓 | 目标、止损 | 止损 < ref < 目标 |
| SELL | 减仓、清仓，或回避（不开仓）。**不是做空** | 失效价（存 `stop_loss_price`） | 失效价 > ref；若给出下行参考价（存 `target_price`），则下行参考价 < ref |
| HOLD / WAIT / NO_TRADE / ABSTAIN | — | 无 | 不校验价位 |

SELL 两个价位的含义：
- **失效价**：向上突破到这个价位，说明看空理由失效。
- **下行参考价**：预计的下跌位置，或者重新买入的观察价位，不是"做空获利目标"。

SELL 选用"失效价在上、参考价在下"的几何约定，与现有 SELL 中 13/19 的多数写法一致，改动最小。

### 2.1 SELL 其他规则

- SELL 档的仓位指"操作后持仓上限"，0 表示清仓或不持有，是合法值。
- 入场字段写"不适用"。

### 2.2 价位与参考收盘的来源

- **ref 来源**：直接复用 `price_ref_registry.build_market_data_pool` 的具名字段 `stock_data.<分析日>.close`。它按表头列名解析，`price_basis` 为 vendor_qfq，缺列时 fail-closed。若分析日那一根 K 线不存在（停牌等），价位方向记为 `unverifiable`。
- **确定性校验**：放在档位最终价位字段解析完成之后，与具体提取路径无关。结果写入 `price_plan_check = {"status": "ok"|"violation"|"missing_required"|"unverifiable"|"not_applicable", "ref_close": ..., "ref_field": ..., "rule": ...}`。

### 2.3 校验失败的后果：fail-closed

当状态为 `violation`、`missing_required` 或 `unverifiable`，且档位原本可执行时，处理如下：
- 档位改为不可执行；
- 动作改为 NO_TRADE；
- 原因码记 `price_plan_invalid`；
- 价位与置信度按现有不可执行规则置空；
- 原始价位保存在 `price_plan_check.raw` 里，供审计。

这与 `price_basis_gate` 的处理方式一致，自相矛盾的价位不得以可执行档流出（A1）。

### 2.4 提示词改动

zh.py 与 en.py 同步修改：
- **研究经理、交易员、风控经理**提示词都写明三件事：只做多不融券、SELL 的含义、各动作的价位方向规则。
- **SELL 价位的写法**：SELL 档的价位写成"失效价：xx；下行参考：xx 或 —"。缺失时必须明写"—"，不得编造。
- **示例**：`MANAGER_VERDICT` 示例同步加入 `p_rel_t10`。
- **键名**：研究员提示词里"不增加新的机读字段"的约束不变，新键只加在研究经理块。

## 3. 可追溯（B3）

| 项 | 做法 |
|---|---|
| 输入快照哈希 | 对数据收集完成后、交给各角色之前的输入池，做规范化 JSON（键排序、UTF-8、无空白）的 sha256。写入 `result_data.input_snapshot = {"algo": "sha256", "hash": ..., "keys": [...], "bytes": ...}`；双档各自计算，共用分析师时两档哈希应相同 |
| 代码与提示词身份 | 写入 `result_data.run_identity`，包含：运行时 commit sha；自定义提示词 `resolved_hash`（已有，原样引用）；各角色解析后的模型绑定（名义模型名、temperature、max_tokens） |
| 实际服务模型 | `llm_call_logs` 新增三列：`requested_model`（请求时的名义模型）、`served_model`（只在响应体确实带 `model` 字段时填写，否则为 NULL，**不得回落为名义模型**）、`system_fingerprint`。现有 `model_name` 列保持原逻辑，以兼容旧统计。流式路径能否取到响应体 `model`，须实现者用测试证明；取不到就填 NULL，不能当作已取到 |
| 报告级汇总 | `result_data.served_models = {角色: [实际模型去重]}`，并给出 `served_model_missing` 计数 |

## 4. B2 测量口径

- **单位**：新契约上线后，每日测量批中每个完成的档位。双档计 2 档，失败档不计入分母、单独计数。
- **无效**：满足任一条即算无效。
  - `forecast.status ≠ valid`；
  - 档位原本可执行，且 `price_plan_check.status ∈ {violation, missing_required, unverifiable}`。
- **达标**：连续 ≥ 100 档的无效率 ≤ 5%。按每日 48 档计，约 2–3 个交易日即可攒够。
- **监测项（不判无效，只在每日小结中报告）**：
  - `p_rel_t10` 的取值个数，以及取值落在 5 的倍数上的占比（检查刻度是否过粗）；
  - 短线、中线两档差值的分布；
  - `p_rel_t10` 与研究经理方向的交叉表；
  - `served_model_missing` 计数。
- **真值审计**：总控逐档核对每一个"无效"，以及抽样的"有效"。

## 5. 放行与影响评估

1. **离线全历史重放（上线前，零模型）**：用新的价位方向校验，在冻结语料上重放全部历史可执行档，列出会被改判为不可执行的档。总控逐档审计后，重新估算 A2 余量。现有 6 档多头式 SELL 和 4 档双缺 SELL 预计都会被拦。
2. **受控实测**：在测试库副本上跑 2 份双档（4 档），核对以下内容：
   - 新键产出；
   - 解析结果；
   - 价位校验；
   - 三个可追溯字段是否齐全。
3. **部署窗口**：避开交易日 16:37 至约 19:00 的每日批，以及回填运行时段。日志中记录契约上线的 commit，作为 A2/B2 的口径分界。
4. **前端**：SELL 档把"目标/止损"显示为"下行参考/失效价"，属于后续前端卡，不是 B1 的出口条件。在前端卡完成之前，现有标签保持不变；方向正确的数据在现有标签下不会被误读为多头止损。
