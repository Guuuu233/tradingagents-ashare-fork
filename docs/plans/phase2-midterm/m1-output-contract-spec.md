## 1. 预测对象和兼容边界

中线契约版本为 `b2.v1`。唯一新增模型概率为 `MANAGER_VERDICT.p_rel_t40`，语义为：

> P(股票从 T+1 开盘到 T+40 收盘的收益 − 同窗口申万一级指数收益 > 0 | 截止时合法信息)。

T+40 是从信号交易日 T 偏移 40 个交易日，不是入场后另持有 40 日。行业归属按分析日解析；标准预测标签来自 P2 的 `return_labels.py`，执行延期收益、T 日收盘研究口径、沪深300 超额、交易成本和风格残差均不替代该目标。相对收益恰好为零时标签为 0。

`p_rel_t10` 与 `p_rel_t40` 并存，原字段及其 b1.v1 语义保持独立：短线继续使用 `p_rel_t10`，现有中线里的 T+10 值仅供原诊断使用。T+40 不依赖 T+10 是否存在或合法；不得改名、复制、插值或从方向、confidence、绝对上涨 probability 推算。短线不要求新增 T+40 字段，出现该字段也不得冒充中线样本。

方向与概率独立；中性、ABSTAIN、风险层 BLOCKED 不自动判废合法概率。M1 不增加交易闸门，不从概率阈值反推方向。提示词示例不出现具体概率数字；可用文字字段清单表达类型约束，不能把占位字符串写成可解析机读示例。

基率主基准严格取 D-075 的 `m200/W0`，其余格仅作敏感性展示。现有 `m1_base_rate.py` 的 `p_m200` 为 0–1 小数；写入本契约时乘 100，不取整，评价再除 100。成熟历史按分析截止时刻 `as_of` 判定，先将其转换到 Asia/Shanghai，再与信号交易日 T 的 15:00 比较：

| 分析截止时刻（Asia/Shanghai） | 可纳入基率的成熟条件 |
|---|---|
| `as_of >= T 日 15:00`（包含恰好 15:00） | `actual_exit_date <= T` |
| `as_of < T 日 15:00` | `actual_exit_date <= T-1` |
| as_of 缺失或不可解析 | `p_base_rel_t40_status = pit_unverified`，基率置 null，不补当前时间 |

此处 T-1 为 T 前一日的日期上界；实际退出日期使用 P2 给出的交易日期，不能把退出日或截止日改成自然日持有期。判定不使用报告创建、运行完成或封存时间代替分析截止时刻。元数据保存原分析截止时刻及其时区；收盘前排除 T 日成熟标签，收盘后及恰好收盘允许 T 日成熟标签。基率不给模型看，也不写入模型输入快照或提示词；基率来源哈希单独存。基率计算版本改变须分开记账。

已有 b1.v1 的 forecast_input/benchmark/data_gap 等键继续保留。任何兼容镜像只能由上述规范键派生，不设第二写入真相源。

## 3. 失败分类、计数与 fail-close

| 状态          | 条件                                                              | error_codes                                                                                          | 是否为解析无效   |
| ------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ---------------- |
| `valid`       | 唯一规范块、唯一键、严格合法整数                                  | 空数组                                                                                                    | 否               |
| `missing`     | 有合法对象但缺 p_rel_t40，或根本没有 MANAGER_VERDICT 块           | `missing_field` / `missing_block`                                                                         | 是               |
| `malformed`   | 块损坏、非对象、重复块/键、类型或范围错误；显式 null 也属类型错误 | `invalid_json` / `invalid_object` / `duplicate_block` / `duplicate_key` / `invalid_type` / `out_of_range` | 是               |
| `node_failed` | 节点调用异常、超时、响应中断，未获得成功的最终输出                | `node_exception` / `node_timeout` / `response_incomplete`                                                 | 否，另计节点失败 |
| `not_run`     | 中线已计划但节点未进入                                            | `node_not_run`                                                                                            | 否，另计未运行   |

优先按节点生命周期区分 failed/not_run；仅成功完成节点后分类 valid/missing/malformed。每个中线分析单元的最终输出仅计一次；既有内部重试只记日志，不增分母。同一输出缺失且类型异常不得双计。解析成功但报告/账本掉字段另记 `report_readback_failed` / `ledger_readback_failed` 管线故障，不能把它改成模型 missing。

所有非 valid 的模型概率均置 null，保留失败状态与审计证据；不得补 50、补方向映射或补基率。fail-close 的范围是正式概率样本纳入及发布验收，不是新增交易 ABSTAIN 规则；正常的其他报告字段可保留。基率缺失不使合法模型概率变无效，但该条不得进入模型对基率的配对增量比较。

计数同时列出：计划中线单元数、尝试数、已完成中线分析单元数、节点失败数、未运行数、missing 数、malformed 数、合法概率数、三处读数一致数。无报告落库的失败要从实验运行清单保留，不能靠 completed 报告反推尝试总数。

已签收门槛照抄执行：

- M1 20×2 重复测量共 40 次尝试，解析无效（missing + malformed）不超过 1 次；不能剔除失败后补跑成“40 次成功”。额外复跑单列。
- 上线后滚动 5 个交易日，解析无效率 = 完成的中线分析单元中 missing + malformed / 中线档完成的分析单元数，不超过 2%；分母为零时记不可计算。
- node_failed/not_run 不混称解析失败，也不能用此分类掩盖未完成的 20×2、串扰或读数缺口；独立披露，工程证据不齐时不得签通过。
- 历史 b1.v1 和未请求的中线档不进入 b2.v1 无效率分母；兼容读取时标历史版本，不给旧记录制造 M1 missing。

**总控已批准缺字段解释：**缺字段逐次置 null、fail-close 并计 missing；批次门槛按签收的“40 次 ≤1 次解析无效”执行。报告、账本读回掉字段属于工程硬失败，分别计 `report_readback_failed` / `ledger_readback_failed`，不得混入模型 missing/malformed 或靠批次解析容许量放行。计数报告必须单独列出这两项管线失败数。

## 5. D-075 评价接口与验收证据

模型 `q_model = p_rel_t40 / 100`，基率 `q_base = p_base_rel_t40 / 100`。同股、同信号日、同版本按既定主运行规则取 created_at 最早的已完成运行，不因概率更好或解析失败事后换一次运行。重复平均只属于 M3。

正式队列仍只纳入 F0 + input_pit_status VERIFIED、版本证据齐全、合法概率及成熟标准标签的样本。方向中性或风险拦截不是额外排除条件。模型全量合格序列与模型/基率配对交集分开报；基率缺失、未成熟、版本缺失等逐项披露。

增量主检验是同日同样本的 `IC_model,t − IC_base,t`，交集过滤后 n_t≥10；秩退化单列不可定义，不补 0。模型和基率的 IC、组差、可靠性并列展示。沿用日等权、平均秩、边界并列分数权重、固定十箱、NW60/NW120 与 95% 双侧区间；有效日期≥60 且两个区间下界均>0，才可按既有结论范围宣称超出基率的排序能力。工程通过不代表增量能力或盈利。

## 6. DAV-1450 路径、风险与实施流程

**路径推荐：按 DAV-1949 最新卡面，M1 先在独立分支开发；DAV-1450 实验结束后若总控采纳修正，再将 1450 修正重底到 M1 之上。** 此顺序优先于计划旧文中“先 1450 后 M1”的排期文字。1450 已冻结实验保持原基线和提示词，不叠 M1 字段；不能把合并候选当原 A/B 结果直接签收。两者均触及研究经理提示词，按已批准流程执行：

1. M1 在独立分支开发；1450 冻结实验保持原基线，实验结束且总控采纳修正后才将修正重底到 M1 之上。
2. 解决重底冲突后核对并记录最终提示词 SHA256、合并代码 SHA、短线兼容和方向/概率独立性，以合并版本建立新的验收记录。
3. **合并版本重新做 M1 至少 20 只股票 × 每只 2 次的重复测量**：冻结输入、独立线程/检查点、固定账户，核实实际服务模型及版本一致，重新核三处读数、失败分母、分布与稳定性诊断。不得沿用 M1 或 1450 各自版本的测量结果作为合并版本验收证据。
4. 按 §3 的 40 次解析门和既有工程硬失败要求出具合并版本验收报告，再交总控裁定；本卡仅写流程，不授权触发测量或模型调用。

按优先级的风险与建议：

1. **高：概率缺失被默认值掩盖或错误改变交易门。** 严格解析、null + 原因、分开记账，fail-close 仅作用于概率和验收。
2. **高：报告/账本取到短线或顶层概率。** 只从中线规范键取值，三处值/状态/版本逐条核对。
3. **高：基率前视或单位混用。** 冻结 m200/W0，存来源与截止证据，0–1 到百分点只换算一次；不足不补值。
4. **高：M1 污染 DAV-1450 冻结实验。** 分支与实验基线隔离，实验结束并采纳后才重底。
