## 1. 结论与约束

建议采用“**一次受控采集 → 内容寻址原始响应库与缓存快照 → 两臂只读使用同一版本 → 在分析开始前分别封存实际 pool 并比较**”。缺失的动态源由实验专用响应重放层覆盖，缓存 miss、未知请求或直连旁路均禁止回源。持久化完整 pool 优先；仅存摘要不足以重建。

必须区分两个目标：

- **供应商输入相同**：同一请求键返回同一份原始响应，来源覆盖、缓存和版本全部可查。外部重放层、只读挂载和网络隔离可以实现这一目标，但需要另卡实现与验收。
- **分析前完整 pool 相同**：包括本地生成的时间、失败账本、类型属性和数组顺序。当前采集器会生成 `retrieved_at`、产业链 `cached_at` 等值；冻结响应并不冻结这些值。因此，在“不替换 collect 返回值、不注入私有缓存、不改时钟/被测逻辑”的约束下，**不能保证每对完整 pool 逐字节相同**。

可实施的交付路径是先建立输入留存与供应商冻结机制，以实际 pool 的严格比较作准入门。严格比较不通过的对不得纳入严格同输入主集。若目标是“每对必然读到同一完整 pool”，需总控另行批准同一 pool 的导入/注入入口或另行预注册等价定义；本文不把这类行为藏在“外部 harness”名义下。**本批严格相等的配对为 0，就停在这个事实上：不放宽规则、不删字段、不放宽来源覆盖、不补抽样本**。不得因零样本在本批内改用规范化口径补足严格主集，也不得通过新增尝试或重跑凑数；原有独立获批的故障重试另按冻结协议留账，不能因严格不等而触发。现有约束不变且本地时间差异存在时，严格主集可能为零，这应在消耗模型额度前发现。

DAV-2014 第一批 5 对继续只作描述性材料、不计入样本；本文通过审查也不自动解锁第二批。DAV-2331 的执行器签字、模型身份、双身份、渲染提示词哈希等原门仍须分别满足。

## 3. 留存对象与不可变证据包

每批使用唯一 `freeze_id`，每对关联原 `pair_id`、固定账户的非敏感标识、trade_date、horizons、price_basis、输入截止时刻/时区、采集开始/结束时刻及来源范围。采集时间跨度必须如实保存；一次采集不代表各源在同一毫秒生成。

### 3.1 三层内容全部可追溯

| 层 | 最少留存内容 | 指纹与重建要求 |
|---|---|---|
| 供应商响应 | 每一来源/备用来源/旁证/分页/正文请求的脱敏请求描述、原始响应正文 bytes、保留的语义响应头、HTTP 状态或类型化失败、请求时间及源数据时点；非 HTTP 通道单独列明 | 对实际保存的正文 bytes 算 SHA256；压缩正文还记录解码规则及解码后摘要。若授权信息出现在 URL/header/body，只在内存中移除或映射为非敏感身份标签，不保存凭据、Cookie 或低熵凭据哈希。清洗改变正文时，标 `sanitized`、规则版本，不能声称它是原始 wire bytes。 |
| 缓存/本地数据 | 实际读取的新闻缓存、行情/财务本地文件、社交归档、日历、行业/证券映射及副本库中会影响采集的表；缺失项、TTL/写入时间同样记录 | 逐文件路径别名、bytes、SHA256、mtime/格式/时效参数；数据库用一致性备份或停写后的静态副本，附逻辑表范围与 schema 版本。不得只复制活库主 db 而漏 WAL，不对活库使用 immutable。 |
| 实际 pool | collect 成功返回、分析师尚未消费的全量对象；另存分析结束前/落库摘要计算时观察到的对象 | 同时保存服务端 canonical bytes 与类型保真表示。O/N 分别封存并核验，不能以“由同一响应库生成”代替实际观察。 |

有条件走“可重建指纹”时，**摘要必须引用仍可获取的不可变对象**：对象 ID/受控存储位置、bytes、SHA256、格式/编码、解码器版本及依赖、转换代码 SHA、全部请求和缓存映射、时钟/随机性影响清单。验收人员在断网环境下取回对象、校验并重建，结果必须匹配归档的 canonical 与类型证据摘要。只有 hash、供应商 URL、重新抓一次或可变目录路径均不合格。无法重现本地时间/对象属性时，必须保存当时的实际 pool，不能用“可重建”兜底。

### 3.2 pool 的双表示

`pool.canonical.json` 的 bytes 必须在观察时使用与服务端相同的序列化规则：`json.dumps(pool, sort_keys=True, ensure_ascii=False, separators=(",", ":"), default=str).encode("utf-8")`。文件就是这串 bytes，不追加换行；保存 bytes 数、顶层键、SHA256 和 `default_str_keys`。此规则是项目现有规则，不宣称通用跨语言 canonical JSON 标准。

另存 `pool.typed.json` 及编码器版本：记录精确 JSON 路径、类型名、文本与附加属性，至少覆盖 `FundFlowText.fund_flow_evidence/fund_flow_evidence_meta`、`StockDataText.price_basis`、公告 envelope/record、DataFrame 的列顺序/dtype/index/逐值、日期/时区、Decimal、NaN/NA/None、tuple/set 等实际遇到的类型。对象图中的别名、重复引用和循环也须明确定义。编码器仅支持审定类型，不遍历整个进程或任意配置对象；未知类型直接标证据不完整，不能无声 `str()` 后宣布保真。

typed 表示不是注入模型的新输入，也不写回 pool。**P2-3 实施前硬前置**：正式输入冻结/对照实施之前，必须实现并冻结字段级 schema、类型白名单、稳定对象引用编号、别名/循环规则及编码器/解码器版本，实际验证“完整对象 → 编码 → 解码 → 再编码”一致，逐项执行字符串附属 evidence、空容器/缺键、日期/时区、NA/NaN/None、Decimal 等反例。实现与离线验收须另卡，且在本文终签后才可启动；本卡不编写编码器或执行反例。未实现、未执行或证据不全时，不能断言完整保真，也不能进入正式冻结/模型分析阶段。不能使用任意 pickle 反序列化。canonical 相等只证明现有摘要口径相同；typed 不等仍须判完整输入不等。文件哈希及清单字段检查不替代完整性审核。

## 4. 在不改 O/N 被测代码下如何观察与冻结

### 4.1 外部观察器：只读返回值，不替换行为

建议后续单独实现实验专用启动器，使用 CPython 3.10 的 `sys.setprofile`/`threading.setprofile`，按**完整文件/函数身份**观察 `DataCollector.collect` 的 `return`，读取将返回的对象后封存；不改磁盘源码、不替换方法、不改返回对象、不写 `self._cache`、不注入池、不改变随机种子/时钟/TTL。**总控已裁定：`sys.setprofile` 只读观察 + 同步等待闸只允许在隔离的 O/N 实验实例上使用，两臂必须对称；生产 `082be047` 一律不碰。** 两臂冻结相同观察器版本、安装范围、事件规则、等待闸和超时策略，差异须先阻断准入；本裁定不扩大到生产、定时任务进程或其他实例。观察器属于有性能影响的运行期插桩，不能声称零侵入。**等待闸会改变耗时，故耗时类指标一律不进 O/N 对照结论**；采集/屏障/分析等计时只用于运维、窗口和资源预算，不比较快慢、提速或性能收益。

公开一手接口依据（2026-10-26 已查阅）：[Python 3.10 sys.setprofile](https://docs.python.org/3.10/library/sys.html#sys.setprofile)、[threading.setprofile](https://docs.python.org/3.10/library/threading.html#threading.setprofile)。return 事件的 arg 是返回值，异常导致返回时可能为 None；profile 出错会被解除。`sys.setprofile` 是线程相关接口，不能靠主线程回调覆盖 `asyncio.to_thread`。后续启动器必须在创建工作线程之前安装 threading 回调，逐进程验证；不假设 Python 3.10 有“为所有已运行线程安装”的接口。

观察器在成功返回处同步封存，外部 admission barrier 等两臂证据齐备后进行**分析前准入**比较，只有同一配对两臂均获 `pre_admitted=true` 才可放行模型网关与分析师阶段。回调仅等待外部放行，不改变原返回值；必须有超时和采集/观察开销计时。实现必须限定在上述总控裁定边界内，无法按边界实现就阻塞，不得改成 monkeypatch。能力验证须待本文终签后另卡授权，使用无模型、无供应商的本地材料。

**P1-2 准入前零模型调用**：实验只接受直接提交的结构化请求，显式固定 symbol、trade_date、horizons 及相应分析参数；**请求体不带 `query` 键**，即使值为 null 或空串也不以“带 query”方式提交，不走聊天/自然语言解析入口，不用预先调用模型生成 user_intent。基线 `api/main.py:3501` 在有 query 时可能先调用意图解析 LLM，collect 屏障不能覆盖该调用；无 query 的结构化双档路径可直接构造意图，但这仍不是零调用的运行证据。

两臂的 **`user_intent` 与 `user_context` 必须相同**，包括实际生效的默认值、导入持仓/约束及合并结果；只比较请求体或令两个对象为空不充分。未来只读观察器须在模型调用前封存与实际执行请求关联的有效对象，记录 canonical/typed 摘要并严格比较；无法定位、无法关联或不同即前置拒绝，不改写其中一臂使其相同。请求参数、意图/上下文及副本库输入均按获批范围准备，不读取或改动生产个人配置。

独立模型网关自实验进程启动起默认关闭，**在分析前准入完成前拒绝所有模型请求**，覆盖意图解析、分析、SDK 重试及其他模型接口；两臂不能绕过网关直连供应商。只有持久化同一 pair 两臂准入结果、请求/进程身份、freeze 根及零请求审计后，才能按该 pair/arm 身份授权后续模型访问，不能提前全局开闸。网关/网络审计必须覆盖“进程启动 → 放行”完整区间，留下两臂各自的**零请求审计记录**：区间边界、策略/日志摘要、请求尝试数、拒绝数、转发数和 token/费用记账状态，不能用缺失日志、服务端成功或失败 fallback 代替零。准入前的尝试数和转发数均须为 0；发现尝试即拒绝并记录前置拒绝原因，不再给该尝试颁发准入，任何已转发请求还须按泄漏事件保留实际消耗。审计不全或存在旁路即停止；不把“网关拒绝了请求”写成“从未发起请求”。

需要显式覆盖异常返回、线程池与子进程、重复 collect/缓存命中、多请求关联、观察器解除、写盘失败、超时与并发关联。profile 不提供业务关联保证，不能只用 thread ID 或股票代码配对；未来实验实例应每臂单任务，并记录 process UUID、完整调用栈标识、请求/pair/run ID 映射。观察器无健康确认或缺一次预期观察事件，由外部监管器在放行前终止该实验，不靠服务端“任务成功”推测观察成功。

结果落库前另观察 `_compute_input_snapshot` 的入参/返回，核对初始 pool 是否被原地修改；若发生修改，分别保留初始和末态，标差异来源，不能以后验 pool 覆盖分析前文件。所有保存路径及每档报告都关联各自观察摘要。若分析中还有临时工具/文件输入，不在初始 pool 中，必须纳入 consumed-inputs；发现未封存额外输入即不能声称完整输入已冻结。

### 4.2 冻结的不是一个目录，而是全部数据入口

未来执行者先根据两臂实际 SHA 做静态入口盘点，建立“逻辑源 → 主源/备用/旁证 → 协议/缓存位置 → 参数及日期范围 → pool 路径”的覆盖矩阵。**入口覆盖清单必须在正式输入冻结/对照实施前实现并冻结**：绑定 O/N 真实版本、全部线程/子进程和实际调用路径，以本地材料验证观察覆盖、缓存/文件/协议映射及额外输入发现机制。§2 是起点，不能当作已实现或已验证完整的入口清单；仅列出字段/域名不算覆盖验收。观察器失效、写盘失败、未知类型、未覆盖路径或协议不支持均阻止放行。此实现和离线验收须待本文终签后另卡开展；如有获批 O2，也必须独立明确插桩授权和验证范围，不能据 O/N 边界自动扩用。

受控预热只能在专用采集沙箱、独立缓存/库中做，不预热生产或 O/N 私有内存，不跑完整 LLM 分析来“顺便预热”。授权执行者记录真实 provider 尝试、状态和缺失。单股票从采集代码可知约有数十个逻辑任务，实际分页/旁证/重试可能更多，预热请求数须实测计账。

对于无法单靠本地文件命中的源，拟用实验专用网络响应重放服务。请求键至少含服务/供应商别名、协议、method、路径、完整语义查询与 body、股票/日期/范围/分页/价格基准、影响响应的非敏感 header、身份类别。凭据只在内存里剥离映射；不能把 method/path 相同但 body 不同的 Tushare 请求合并，不能忽略日期/分页/来源版本。重复请求绑定冻结的同一结果；若协议需要有序会话/失败序列，则保存每臂独立、相同初态的会话状态及逐次事件，不能两臂共用一个递增游标争抢响应。语义不确定时拒绝匹配，不做模糊近似。

HTTP(S) 重放需在实验沙箱内验证 TLS 信任、各 SDK 的代理服从性与证书固定行为；禁止关闭 TLS 校验或修改宿主系统信任。Baostock 等非 HTTP 通道不能假定支持 HTTP 重放，须分别验证协议代理或已存在的本地输入通路。某通道无法透明覆盖就列为阻塞，不用空数据替代正常数据，也不能修改 provider 返回值伪装覆盖。本文不指定未验证的第三方工具版本/命令，也不声称现成代理已支持全部入口。

重放层的冻结 miss 必须记录并拒绝请求，不自动真实回源；供应商失败响应也按冻结事实保存。仅阻网导致“两臂都无数据”不能作为输入可比性成功：同样空缺必须额外通过数据覆盖/PIT门，且不得通过阻断某个不一致的旁证来制造一致。

### 4.3 隔离与发布快照

1. 静态采集完成后校验全清单，冻结时间截止与来源/PIT状态。对无法确认发布时间或有效时点的源标 UNVERIFIED，晚于截止为 FAILED；相同响应不代表没有前视偏差。
2. 活 SQLite 数据只通过获批一致性快照流程取副本；freeze 使用关闭连接、无待提交 WAL 的静态快照。报告库/任务库保留 O/N 各自独立可写副本，**不能把整个 DATABASE_URL 设只读**来凑缓存只读。
3. 同一快照在两臂沙箱中以相同逻辑路径只读挂载；可用同一内容对象或两份逐文件摘要相同的只读副本。路径别名和实际挂载映射进入审计清单。文件权限 0444/目录 0555 只作辅证，使用 OS 强制只读挂载或独立服务账号权限；证明进程不能换目录、改 symlink 或写挂载外同名路径。
4. 只在实验进程中配置 `TA_DATA_CACHE_DIR` 到合法的沙箱绝对路径（在源码 worktree/releases 外），盘点各模块真实读取的位置。历史文件中影响 TTL 的 `ts`/mtime 原样保留，不改 ts 延长有效期；过期请求交给已冻结的重放层，不改时钟绕过 TTL。
5. O/N 从干净实验进程启动，空的进程内缓存由相同冻结响应自然生成，初态和后续命中留证。不反序列化或编辑 provider 私有类缓存。所有可写目录仅为各臂输出/任务库/运行日志，不能作为未经登记的数据缓存回落；发现数据侧写尝试，阻断并记录，按审定规则判废。
6. OS 网络策略限制实验沙箱：数据访问仅到重放服务；正式获批分析时模型访问仅到冻结的模型网关。默认拒绝其余出站、DNS/直连/IP及宿主代理旁路；网络审计作为证据，代理环境变量不是阻断证明。模型网关不得充当任意 CONNECT 转发通道。先用无模型材料验证策略；本次不创建或修改防火墙。
7. freeze 发布后不再预热或修补。每对开始前和结束后复核快照根、挂载与策略摘要；miss、只读写入失败、异常直连或内容变化立即停新增请求、保留该对原尝试，重新制包要重新审批。

macOS 本地能否提供以上进程级隔离、只读挂载和完整通道覆盖，本轮未实测；可优先在专用 VM/容器沙箱验证，但必须证明获批解释器/依赖与生产锁定环境等价，不能随便换一套 Linux/Python 后沿用生产门禁结论。若当前机器做不到强制隔离，报告“平台能力待验证”，不降格成 chmod 后宣称已冻结。

## 5. 等价判定：证据齐备后再比较

建议每对输出以下独立状态，不把多个“相同”混成一个布尔值：

| 状态 | 通过条件 | 否则处理 |
|---|---|---|
| `archive_complete` | 原始响应/缓存/实际 pool 全部对象可读、摘要与类型编码检查通过，覆盖矩阵无未知入口 | 缺证据，停止，不判同输入 |
| `vendor_equal` | 消费数据都来自同一 freeze；每个实际输入请求及本地读取均能映射到同一对象，重复次数/会话语义可核；0 未登记数据、0 外部数据回源 | 供应商/覆盖不等或未证实，整对单列 |
| `pool_raw_equal` | 两臂分析前 canonical bytes 的 SHA256/长度/键及字节比较相同，typed 表示按冻结规则相同；此状态只用模型调用前已存在的对象判定 | 严格输入不等；不予分析前准入 |
| `pool_normalized_equal` | 在保留原始材料后，按总控已批准的精确路径/变换规则重算两份完整 pool 的规范化摘要、类型证据及结构 diff，无剩余差异 | 差异不可豁免；单列，不事后扩白名单 |
| `input_pit_status` | 每项有效/发布时间和请求截止的关系已证，缺时点不能判 VERIFIED | UNVERIFIED/FAILED；不以摘要相同替代 PIT |

`vendor_equal` 比较的是实际输入语义覆盖。允许重复读取同一不变对象，但次数、顺序仍完整记录；出现某臂独有的来源/分页/旁证，必须列差异并解释，不能仅比较摘要集合后通过。若运行路径导致实质输入额外读取，判不等。消费审计不能证明一个对象已进 prompt；还需 pool 路径/后续工具关联。模型响应、经理生成内容、后验 validation 属输出，另外留档，不能混作原始输入；也不能用它们归因供应商差异。

### 5.1 P1-1：分析前准入与最终证据有效分开

设 `pre_admitted` 为**分析前准入**。它只依赖模型调用前已存在且归档成功的证据：`archive_complete && vendor_equal && pool_raw_equal && input_pit_status=VERIFIED`，另须请求无 query、两臂有效 user_intent/user_context 相同、网关完整零请求审计、类型编码及入口覆盖前置验收成立。`archive_complete` 此时只检查初始输入对象；`vendor_equal` 与 PIT 此时只判断截至等待闸已消费的输入，不引用尚未生成的报告或后续工具输入。后续输入及完整运行期覆盖另归最终证据核验。两臂同时满足才持久化为 true 并解锁该 pair 的模型访问；任一拒绝两臂都不放行。它不要求落库回读，不把后验输出条件伪装成前置条件。

设 `final_evidence_valid` 为**最终证据有效**，只在已放行后核验：两臂/双档完成及落库回读、服务端 `input_snapshot` 与初始/末态观察摘要对应、前后对象差异、冻结根/数据出网/额外输入审计、模型和双身份/协议等既有门。模型输出、后验 validation 不纳入初始输入相等判断。最终失败标为 false，保存原值与原因；**不把已发生的 `pre_admitted=true` 改回 false，不撤销已放行计数、不抹掉消耗**。只有前置准入与最终证据均有效的对才属于严格有效子集；不能用归档后的新规则重新筛选初始请求来改写历史。

在结果暴露前按预注册口径冻结统计分母、各失败定义及重试规则，台账按原 pair_id 逐项记数并附原因：

| 计数 | 定义与报告要求 |
|---|---|
| `planned_pairs`（计划对数） | 冻结的原计划配对全集及名单/规则 SHA；不因拒绝、失败或后验剔除缩小。未启动/因停批未完成部分另记 `not_started_pairs`，并列待判的前置处理中数量。 |
| `pre_rejected_pairs`（前置拒绝） | 模型调用前已拒绝的配对；按严格输入不等、上下文不等、PIT、覆盖/类型、零请求审计、超时等冻结原因逐对留存，拒绝不是未计划。 |
| `pre_admitted_pairs`（已放行） | 历史上已取得两臂前置准入的唯一配对；最终失败仍在这个分母中，不以模型是否返回成功倒算。 |
| `single_arm_failed_pairs`（单臂失败） | 已放行后恰有一臂失败/缺失的配对，记录臂、阶段、原因、重试与全部调用/消耗；双臂失败另外计数。 |
| `post_invalid_pairs`（后验失效） | 已放行后 `final_evidence_valid=false` 的配对，按证据/模型/身份/原地变更/冻结破坏等原因记录；其中可包含单臂失败，交叉关系和去重总数明确展示，不能把重叠计数相加冒充独立配对数。 |
| `strict_valid_pairs`（严格有效） | 已放行且最终证据有效的配对，另报尚在执行/待终核数量；严格相等为零或最终严格有效为零均如实报告，不放宽规则、不补抽。 |

队列中各配对保留唯一当前阶段和追加式历史；报告时解释 `planned_pairs` 如何分解为未启动、前置处理中、前置拒绝与已放行，已放行又如何分解为最终有效、最终失效与待终核。重试另设 attempt_id，不能把重试算新计划对或覆盖初次失败；故障重试只在原独立授权范围内进行。

**被事后剔除的配对不得悄悄从分母删掉**：计划执行/覆盖报告保留计划对全集；可靠性、失败率和成本报告按预注册的总尝试或已放行口径报告，列出每个明确分子/分母、各阶段未完成和失效原因，不能一律改成严格有效对数。原有停批阈值沿用其冻结分母；不按结果修改。严格有效子集上的效应估计单列其实际分母，并同时披露全计划流失路径、O/N 失败/失效差异及选择偏差风险；**严格有效子集只代表该子集，不外推到全部计划配对、股票总体或整体收益**。未获批缺失值处理/敏感性方案时，只报证据不足，不将缺失当零、不补造整批效果；规范化集另行裁定。

### 5.2 规范化只能作为单独报告

总控 10-20 已允许剔除经证实无内容影响的 `retrieved_at`，新闻 `source_hashes` 按集合核查；资金流校验和和 `global_indices` 状态不可剔除。实现仍须事先枚举本次完整 pool 的精确路径及规则 SHA，保留数据截止/交易日、来源、数值、价格/新闻时点、正文、失败/覆盖状态。不能把所有名含 time/cache 的字段统一删除；例如产业链 `cached_at` 是否可以剔除尚未获本卡授权。

`source_hashes` 规范化既报已批准集合比较，也报每元素重复次数/列表长度，出现重复次数变化须解释；不得排序整个新闻/资金流列表。动态数组需保存稳定记录标识到具体路径的映射，规则/路径在结果暴露前冻结。新记录导致未批准路径出现时按差异处理，不能写通配符或事后自动添加路径。

现有 `scripts/phase2/compare_input_snapshots.py` 可以比较非空合法快照和输出字段差异，但**不会根据摘要重建 pool**，其 flatten 也不完整表达所有空容器/类型差异；CLI 返回 0 仅表示执行结束，不表示等价。不得拿空对象/null hash 相等作通过，不得删除保护字段 `hash/algo/keys/bytes`。在真实 pool 上应用获批变换后重算 canonical/typed 摘要，另外做包含键存在性、空容器、数组长度、类型与原值的结构比较；这是后续外部验证器职责，不修改现有比较器假装已经具备能力。

`comparison.json` 至少含 pair/arm/run/report 身份、freeze 根摘要、前后 pool 摘要、typed 摘要、合法快照检查、两档回读、原始差异/规范化差异的精确路径与对象引用、白名单/算法/验证器 SHA、上述各状态、**独立的 pre_admitted/final_evidence_valid 及各自时间和原因**、有效 user_intent/user_context 摘要、网关零请求审计、预注册计数类别和 attempt 账本引用。规范化相等只能标“按批准口径可比”；**不能改写为原始输入完全相同**，能否另成统计集仍由总控裁定。

### 5.3 必须击穿的反例（后续验收计划，本次未执行）

| 场景 | 预期证据/结果 |
|---|---|
| 同一冻结 fixture，两臂重复读取 | 全对象可回取；严格字节/typed 相同，且无额外数据出网，才可能通过 |
| 300054 型：一臂缺五天历史旁证，即使主选值不变 | records/来源覆盖/typed 属性差异，`vendor_equal` 或 `pool_raw_equal` 不通过；保留五条日期和值证据 |
| `FundFlowText` 文本相同但附属 evidence 不同 | canonical 可能相同，typed 必须判不等 |
| 仅本地 retrieved_at 不同 | raw 不等；仅已批准精确路径可使 normalized 相等；不改变严格结论 |
| source_hashes 换序与重复次数改变 | 两种分别报告；集合相等不掩盖重复次数/原始列表差异 |
| 新闻 TTL 到期、缺页、额外正文、未知请求、非 HTTP 旁路 | 同一冻结响应重放或明确拒绝；任何真实数据回源/未覆盖输入均停新增请求 |
| 只读文件写入、symlink 逃逸、回落到默认宿主缓存 | OS 拒绝且有日志；证据缺失或逃逸成功不得通过 |
| 空/损坏 pool、未知类型、观察器解除、线程漏观测、并发错配 | admission barrier 不放行；无模型消耗时就报告缺证据 |
| 观察后 pool 被改、空容器与缺键互换、服务端末态 hash 不符 | 保留前后差异，不用末态替换前态；final_evidence_valid=false，保留历史准入及分母 |
| 同样两臂都为空或同样含未来数据 | 等价与覆盖/PIT分开；不可作为有效样本 |
| freeze 文件被换、manifest/对象摘要损坏、断网重建失败 | 完整性门失败；不发布 freeze、不运行分析 |
| 带 query、两臂有效意图/上下文不同、准入前模型请求尝试或网关审计缺失 | 前置拒绝，双臂不放行；网关拒绝请求且保留尝试/拒绝/转发计数，不能将失败 fallback 当零请求 |
| 已放行后单臂失败或末态证据失效 | pre_admitted 及已放行分母保留，final_evidence_valid=false，单臂失败/后验失效交叉计数、原因及全部消耗可追溯 |
| 严格相等对数或最终严格有效对数为 0 | 停在零的事实，不删字段、不放宽规则/覆盖、不补抽；仅报计划流失与阻塞，不报告子集外效果 |

任何反例未执行、无法复现或没有日志/对象指纹，都只能是“设计有条件可行/待验证”，不能写端到端 PASS。历史第一批缺失材料不能由新机制追溯补造。

以下为规划估算，非实测报价/工时承诺，不新增依赖或自动扩大已有额度：

| 项目 | 代价/风险与控制 |
