### WP4：干净启动与继承连接隔离——最早硬止损门

**证据缺口。** 沙箱前建立并显式继承的 AF_UNIX FD 在沙箱内 `send` 返回 25；没有 recv 证据，不称为对端收到或供应商泄漏。`close_fds=True` 对照的 EBADF 只证明该 FD 关闭，不证明完整服务没有继承通道。

**交付物。** 实验专用干净启动契约与启动器；允许 FD/标准流/审计句柄清单；子孙进程生命周期及句柄清理；从启动前即生效的 OS 约束与独立监管轨迹。覆盖 TCP/UDP/Unix、IPv4/IPv6、native 调用、宿主代理、DNS及允许端点转发逃逸；禁止任意 CONNECT。建立审计健康故障时关闭准入的控制路径，不靠进程内 profile 自报健康。

**依赖。** V 先于其他高成本验证，复用 DAV-2346 的合成旁路事实；B 需 G1，通过与 WP2 共同冻结的进程/请求身份契约，提供后续协议包可用的隔离边界。

**验证及退出条件。** V 必须用沙箱外可成功的对照、预连接/显式传入的 FD、标准流/审计通道和子孙进程证明清理或拒绝；需要声称传输成功/失败时同时记录本地对端 recv 字节数与摘要，不能只靠 send 或 ENOENT。B 必须在完整获批启动链证明仅允许句柄保留，无旁路，监管覆盖启动、准入、结束/故障收尾，无审计缺口；监管失联不得放行。仅关闭一个 FD 不退出本包。

**未知依赖。** 宿主进程级沙箱对预建连接/共享 mapping/句柄传递的精确能力、允许标准流是否可转发、子进程启动方式、VM 等价性及可用权限。不得默认 Python 层关闭 FD 就涵盖 native/子进程。当前机器不可强制且替代环境未经批准或不等价，**整体止损**；不修改宿主系统信任/生产网络作为补救。
