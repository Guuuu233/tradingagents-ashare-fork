**WP4 的规模边界。** 2.5–5 的假设是现有锁定解释器/依赖下的一套单机 macOS 实验边界、一个外部启动器管理 O/N 两个根进程、其线程及受管子孙进程；进程创建前施加同一类沙箱约束，监管器、模型网关、重放服务是显式允许端点，句柄只允许审定标准流/审计用途。完整监管含“启动前准备→创建/import/工作线程→等待闸→放行或拒绝→结束/崩溃收尾”的连续记录与故障闭锁，不是只包住 collect。下端能直接复用本机局部策略，上端在同一机制内补全 FD/native/子进程及允许通道反例。现有证据**不支持**“所有启动机制/全部环境均可在 5 人日内完成”；需 fork/spawn 多机制适配、新 supervisor/系统组件、迁移或无法形成完整轨迹时，此槽位失效，按 WP4-V 止损而非扩称更宽包干区间。

**WP5 的具体协议边界。** “Baostock 通路与同类会话适配”现明确收窄为**一个 Baostock 自有 TCP 流协议族**，不是另一个尚未命名的供应商协议。当前基线 `cn_baostock_provider.py:98`、`:118`、`:131` 可见 AF_INET/SOCK_STREAM、UTF-8 请求加换行、响应结束标记 `<![CDATA[]]>` 加换行、常量定义的消息头和 zlib 压缩分支；这只是源码观察，不是 wire 实测或供应商契约认证。“同类”仅指同一 SDK/同一帧族内登录、查询、结束会话及压缩/非压缩、分片、重连/失败序列，不能据此纳入新协议。TCP/UDP/Unix 的合成阻断反例归 WP4；本包不把 UDP/DNS/QUIC/Unix 当已知数据协议。合法代表性录制材料/本地协议材料、具体消息类型和依赖版本均待 WP2/5-V 核定；4–8 只对这个有限族的上述份额成立，缺材料、新帧族、加密/握手无法透明处理时不能支持上端，停止重估。

**WP7 的已知客户端族与数量边界。** 本轮仅静态查看文档分支所带源码，不导入 SDK/不出网：① **requests 直接 GET/POST**，包括 `cn_akshare_provider.py` 的直连旁证、`cninfo_disclosure.py` 的 form POST、`cn_investoday_provider.py`/`cn_fuyao_provider.py` 的请求；② **Tushare 语义 POST 封装**，`industry_linkage_provider.py:187` 与 `tushare_global_news.py:169` 用 requests 提交 JSON，不能冒称已验证官方 tushare SDK；③ **Akshare SDK 懒导入**，`cn_akshare_provider.py:791`、`industry_linkage_provider.py:605`，SDK 内实际传输/代理/TLS 路径尚未核实。①②可共享传输适配但各自语义请求键必须验证；③能否复用相同机制是预算前提。业务 API/域名、实际客户端实例、重试/分页和信任配置的**数量均待 WP2-V 冻结**，导入行不是完整入口数。HTTPX/OpenAI 等模型客户端归 WP3，不能又按 WP7 收一次；若数据入口另发现 HTTPX/aiohttp/其他传输或特殊 TLS，也须登记并在此槽位外重估。3–6 的上端只覆盖至多两组可共用机制的传输/信任配置及表列语义形态；这是明确的规划容量假设，不是观测数量。超出时不得删入口维持数字，应停并重估，因而目前不能给覆盖全部实际 SDK 的可靠宽区间上限。

## 3. 七个工作包与退出条件

### WP4：干净启动与继承连接隔离——最早硬止损门

**证据缺口。** 沙箱前建立并显式继承的 AF_UNIX FD 在沙箱内 `send` 返回 25；没有 recv 证据，不称为对端收到或供应商泄漏。`close_fds=True` 对照的 EBADF 只证明该 FD 关闭，不证明完整服务没有继承通道。

**交付物。** 实验专用干净启动契约与启动器；允许 FD/标准流/审计句柄清单；子孙进程生命周期及句柄清理；从启动前即生效的 OS 约束与独立监管轨迹。覆盖 TCP/UDP/Unix、IPv4/IPv6、native 调用、宿主代理、DNS及允许端点转发逃逸；禁止任意 CONNECT。建立审计健康故障时关闭准入的控制路径，不靠进程内 profile 自报健康。

**依赖。** V 先于其他高成本验证，复用 DAV-2346 的合成旁路事实；B 需 G1，通过与 WP2 共同冻结的进程/请求身份契约，提供后续协议包可用的隔离边界。

**验证及退出条件。** V 必须用沙箱外可成功的对照、预连接/显式传入的 FD、标准流/审计通道和子孙进程证明清理或拒绝；需要声称传输成功/失败时同时记录本地对端 recv 字节数与摘要，不能只靠 send 或 ENOENT。B 必须在完整获批启动链证明仅允许句柄保留，无旁路，监管覆盖启动、准入、结束/故障收尾，无审计缺口；监管失联不得放行。仅关闭一个 FD 不退出本包。

**未知依赖。** 宿主进程级沙箱对预建连接/共享 mapping/句柄传递的精确能力、允许标准流是否可转发、子进程启动方式、VM 等价性及可用权限。不得默认 Python 层关闭 FD 就涵盖 native/子进程。当前机器不可强制且替代环境未经批准或不等价，**整体止损**；不修改宿主系统信任/生产网络作为补救。

**工作量。** V **1–2**，B **1.5–3**，合计 **2.5–5 人日**。依据为已有一个继承 FD 反例和局部关闭对照，但启动链、允许句柄、native/子孙进程及监管必须重新建立完整证据；不计 WP3 的业务网关建设。

### WP2：入口覆盖与请求关联

**证据缺口。** 每臂 27 个并行任务加产业链、社交、daily-basic、正文等附加通路只是静态起点；主线程 profile 会漏 executor，观察器被清除会静默漏观测。不能把任务数当成 SDK/协议数。

**交付物。** 绑定实际双臂版本的“入口→主源/备用/旁证→协议/缓存→pool/后续输入”矩阵；全部 collect、有效 `user_intent/user_context`、末态摘要观察点；进程/请求/pair/arm/run/attempt 映射；两臂对称的只读 profile、同步等待闸、外部健康确认与故障闭锁。

**依赖。** V 的入口盘点/关联技术部分在 WP4-V 后盘点并冻结协议范围，先供 WP5/7-V 核实；V 内跨包证据汇总留到七包技术记录齐备后收口，不作为 WP5/7-V 开始的前置。WP1-V 可并行定义对象契约。B 需 G1、WP1-B 编码器与 WP4-B 启动边界。只接受无 `query` 键的结构化请求，不能通过新聊天路径扩展范围。

**验证及退出条件。** V 明确每条准许路径的观察位置、线程/进程安装时机、业务关联以及不支持项；B 用无外部调用材料覆盖 `asyncio.to_thread`、缓存命中/重复 collect、异常/超时、既有线程/子进程、并发错配、写盘失败和主动解除 profile。有效 intent/context 必须按真实生效对象关联，不能只比请求体或 ticker/thread ID。缺任一预期事件、未知输入、观察健康失败时闸保持关闭，初始/末态分开封存且返回对象身份与内容不变；不能改成 monkeypatch、替换返回值、写私有缓存。所有获批路径均有证据、所有不支持路径均拒绝，才退出。

**未知依赖。** 动态 provider/SDK 内部调用边、安装前已存在线程、子进程与跨语言调用关联、后续工具输入位置。必需入口无法只读观察/关联就**整体止损**；不以缩减来源、静态清单或“服务成功”代替覆盖。

**工作量。** V **1–2**，B **2–4**，合计 **3–6 人日**。依据为已有两臂静态矩阵但只有 8 项局部 profile 断言；实际工作量来自关联与故障路径，而非重新做一次 27 项列表。类型实现归 WP1，OS 监管归 WP4。

### WP5：非 HTTP 响应重放——协议硬止损门

**证据缺口。** Baostock socket connect/send/recv 通路不能假定服从 HTTP 代理。DAV-2346 仅测试阻断/旁路，未验证协议重放；UDP syscall 拒绝不等于 DNS/QUIC 协议验收。

**交付物。** 按 WP2 矩阵列出的非 HTTP 协议清单、匹配/状态机契约、透明适配及会话事件归档；每臂相同初态且独立游标的响应重放，涵盖分片、重连、顺序失败/重试及结束状态。响应对象复用 WP7 的存储接口，不另建公共对象库。

**依赖。** V 需 WP4-V、WP2-V 的入口/关联技术部分，不等 WP2-V 的 G1 证据汇总；B 需 G1、WP1/2/4-B 及 WP7 公共对象接口冻结。WP5-B 与 WP7 HTTP 适配部分可并行，不能等到末期才发现协议不支持。

**验证及退出条件。** V 须基于获批可用的离线材料确认每种必需协议是否能在不改 provider 返回值、不用真实供应商、不关闭安全校验的条件下透明重放；没有代表性材料只能记 UNVERIFIED，不能退出。B 须验证相同请求/会话得到相同 bytes、错误与状态，两个臂不争抢一个游标；未知帧、缺页、顺序错、未登记请求、重连到真供应商均拒绝并留证。阻断后两臂都空不能通过覆盖/PIT门。

**未知依赖。** Baostock 登录/会话字段、请求与响应边界、native SDK 传输路径、潜在会话加密、材料使用许可；矩阵若再发现其他非 HTTP 族须列名重估，不猜测工具已支持。代表性材料不可获得、协议不能透明覆盖或必须改被测逻辑时，**整体止损**；不删除该来源、不回退实时数据、不用空结果伪装冻结。

**工作量。** V **1.5–3**，B **2.5–5**，合计 **4–8 人日**。按“已识别 Baostock 通路和同类会话适配”的有限范围估计；没有实测吞吐/协议开发工时支持可靠上限。未知协议族不纳入 8 的兜底。

### WP7：HTTP(S) 数据冻结重放与公共响应库

**证据缺口。** 原设计定义了请求键和内容寻址目录，尚无完整响应库、SDK 接线、TLS 服从性与断网回取交付。本包补足“完整建设”中容易被六包标题遗漏的数据面。

**依赖。** V 需 WP4-V、WP2-V 技术部分的客户端/协议矩阵，不等其 G1 汇总；B 需 G1 及 WP1/2/4-B，公共接口在 G1 冻结后优先完成。

**验证及退出条件。** V 逐一验证已登记 SDK 的代理/TLS/证书固定约束及合法离线材料可用性；不得关 TLS 校验或修改宿主系统信任。B 验收 body 不同、分页不同、失败序列、过期 TTL/正文补抓/备用源等不误匹配，未知请求不回源；对象损坏、缺页或回取失败不得发布 freeze；只存 hash/URL 不算可重建。清洗改变 wire bytes 时标 sanitized 与规则版本。真实采集材料如未来获批，必须重新做来源、覆盖与 PIT 验收，合成响应通过不能代替真实预热授权。

**未知依赖。** 各实际 SDK 的代理/信任接线、证书固定、认证字段对语义匹配的影响、新闻/数据存储权限及离线材料代表性。必需客户端不能透明重放且无合规替代时，**整体止损**。不读取个人配置/凭据来填未知项。

**工作量。** V **1–2**，B **2–4**，合计 **3–6 人日**。依据为公共存储/发布/回取及多维请求匹配都尚未建设，另有 TLS 接线未知；不重复 WP5 会话适配、WP3 模型网关和 WP6 缓存只读工程。

### WP1：typed 编解码器

**证据缺口。** canonical 将相同文本而 evidence/meta/price_basis 不同的对象算相同，类型/别名也丢失；尚无 typed 实现，不能称其已测失败或已往返通过。

**依赖。** V 复用已有类型碰撞，结合 WP2-V 技术部分确认实际类型范围；B 需 G1。先冻结 schema 让下游接入，不将注入同一 pool 当作编码器交付。

**未知依赖。** 动态分支实际出现的对象类型、pandas 扩展 dtype、图结构规模、峰值内存与稳定引用语义。无法完整保真或必须改变输入对象时停止该路线；不得声称完整 pool 已保存。

### WP3：独立网关与全程零请求审计

**证据缺口。** 原 16 项只验内存记账：每臂 0/0/0 与攻击 13/13/0，未建真实网关/SDK 拦截。后者是拒绝尝试，绝不能叫零请求。

**工作量。** V **1–1.5**，B **2–3.5**，合计 **3–5 人日**。依据为内存台账可复用但传输拦截、身份持久化、故障闭锁和审计接线缺失；不重复计 OS 管控或 HTTP 数据响应库。

### WP6：只读冻结集成验收

**证据缺口。** 局部 OS 拒写不代表完整服务冻结。mmap 用只读 FD 申请写映射得到 EACCES，不能算可写 FD/既有 mapping 已被沙箱拦住。既有指纹和两次端口快照也不能独立认证宿主全程零调用/零改写。

**交付物。** 所有数据缓存、静态库、TTL、路径别名与只读策略清单；各臂独立可写任务/报告/日志目录；freeze 根和三层对象断网回取；跨包红队矩阵、`comparison.json`、准入与最终证据两套状态及预注册追加式账本；完整证据包及独立复核记录。
