# TradingAgents-AShare 增补整合施工计划 v1

日期：2026-09-06。状态：待用户／Cursor批准的施工计划，不是派工、提交、合入、部署或真实采集授权。

**目标：** 在保留已交付能力和原有未完成工作线的前提下，落实用户已确认的研究档位，完善证据贡献与命题审查，并建立可验证的收益评价条件。

**技术栈：** 现有Python 3.10、FastAPI、LangGraph、SQLite、React/TypeScript/Vitest；外置MediaCrawler独立环境。无需因本计划升级依赖。

### 3.2 本计划提出的实施契约，须随计划审定

1. 解析：显式合法列表→采用；显式包含任意非法值／空列表→验证错误；未提供→按明确文本意图推断，否则short。显式单档与文本冲突时保持显式档，返回非阻断提示。不把Pydantic默认值误认为用户显式选择。
2. 请求状态保留requested、resolved、resolution_source；新配置标识建议为 `horizon_profile_v1`。字段最终命名集中定义一次，复用现有horizon，不新增同义运行模式。
3. 预测评价以规范交易日T为起点、交易日历定位T+10/T+40，严禁不足日期缩短窗口。是否允许该T收盘价作研究基准取决于cutoff前已可得；不可得则标缺失，不偷偷移起点。
4. 策略收益另用可执行入场时点，最早在决策产生之后；与预测基准收益分开。用户确认T+10不等于授权使用决策前价格成交。
5. 主预测事件建议明确为目标日相对研究基准的正收益（收益口径待V-01验证）；含现金分红的总收益和价格收益不能混用。V-01须冻结可用标签口径后才能发布校准成绩，禁止LLM自行决定。

第3—5项涉及收益口径而非仅UI，若无法形成可验证数据方案，继续交付机制功能，但阻断收益评价，不用猜测填满统计。
