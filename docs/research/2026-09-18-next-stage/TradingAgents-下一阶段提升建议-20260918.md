# TradingAgents 下一阶段提升建议：保留推理架构，建立可验证的学习闭环

核查日期：2026-09-18。性质：研究建议，**不是已批准施工方案**。

依据：用户提供的 `tradingagents_chat_full.md`、本地当前代码和验收记录、生产库只读查询、线上 `/healthz`，以及文末原始研究资料。未修改项目代码、生产数据、模型绑定、提示词、开关或部署。没有运行全量回归；动态探针仅执行了从现有源码原样提取的 OOS 分类函数和终态拒绝分类函数。

**17:45 后根据 Claude 评价复核修订**：样本供给诊断提升至 P0，与最低限度封存并行；纠正“仅启动回填”——报告完成落库也会触发；区分 DAV-998 结算缺陷与预测时 ABSTAIN；补成本与样本量估算。

## 一、结论

建议保留现有「分析师 → 多空辩论 → 研究经理 → 交易与风控裁决」主链，下一阶段围绕三个问题建设：

1. **这次判断究竟预测了什么，何时才算对错？**
2. **结果出来后，究竟是证据、推理、裁决还是执行出了问题？**
3. **加入经验后，在同样的新样本上是否真的比不加经验更好？**

传统量化框架的存在不能证明 LLM 分析无效；LLM 能写出合理解释，同样不能证明其有预测优势。需要比较实验，而不是先把 LLM 降为摘要工具，也不是先相信多 Agent 必然更好。

FinCon 的原始研究确有「复盘—更新投资信念—反馈相关 Agent」机制，可以借鉴其经验反馈思路；这不是我们的系统或 A 股应用已经有效的证据。[1] 《The Alpha Illusion》提出时间完整性、交易摩擦、反事实稳健性、概率校准、数值执行和多 Agent 拆分评估等要求；这些检验可以用于约束现有架构，不必直接采纳其替代架构。[4]

**下一阶段不是再做一遍已有模块，而是把已有的统计、案例和评测模块接成真正可靠的闭环。**

## 三、优先级 P0：样本供给与可信封存并行

### 0. 先查样本供给漏斗，但不为凑 VALID 放宽守卫

同日 17:45 后只读事务快照：全库 796 completed，analysis_status 为 NULL 731、ABSTAIN 39、VALID 24、INVALID_RUN 2；24 条 VALID 全在真实账户，生成于 9 月 4–9 日，分析基准日落在 8 月 19 日至 9 月 8 日。“8 月17、9月7”按基准日分月，不能解释为产生于两个月。VALID 也不等于已结算、期限正确、概率可评估或正式 cohort 合格。

上海时间 9 月 10 日以后只有 4 条 completed，均 ABSTAIN：

| 报告 | 已持久化原因 | T+1 结果是否已写入 |
|---|---|---|
| `6350b744…` | 经理采纳了证据覆盖不足的 claim | 是 |
| `f8c59465…` | 资金证据 not_checked / 方向阻断 | 是 |
| `5fd6de0b…` | 把缺乏可回溯证据的 priced-in 当成事实 | 是 |
| `e129c8e4…` | 采纳尚未裁决的 material claims | 是 |

因此 4/4 是 completed 子集的观察，不是每天大量独立分析的总体失败率。同期真实账户还存在 126 条 failed、1 条 running（实时状态会变化）；126 条均创建于 9 月 18 日，其中 117 条错误文本包含 5xx 标记。这只是错误文本分类，不足以认定全部同根因，也不能当独立预测样本。

诊断应按：请求 → 正常完成/运行失败 → VALID/ABSTAIN → 真正前向资格 → 到期 → 成功结算。近期优先查上游运行失败、经理裁决合规与资金证据链，不预设都是缺数据，也不把旧回填缺陷当现时 ABSTAIN 的直接原因。

当前代码的 `is_terminal_refusal_code` 对 `eval_date_not_closed`、`future_eval_date`、`calendar_unavailable`、`vendor_timeout` 和未知拒绝均返回 False；相关源码切片探针 7 项符合预期。当前 historical_cases 121 条已有数值结果，缺数值 0；这不证明所有 completed 都已归档，也不是验证了全部 T+5/T+10/T+40。上述四份 ABSTAIN 的 T+1 也已存在，说明“结算成功”并不会把弃权改成 VALID。

**调整后的优先级：P0-A 样本供给诊断/针对性修复，与 P0-B 最小预测封存同时推进；P0-C 到期结算、独立定时重试及标签隔离随后闭环。** 不先建设庞大的实验平台，但最小封存不能等供给稳定后才补；已经过去的预测时间不可事后补造。

### 1. 给每次预测增加不可变的“预测封存单”

以下是建议的逻辑字段，并非宣称现有 schema 已包含它们：

- 预测对象、事件定义、期限和基准；
- 数据可见截止时刻、预测完成/封存时刻、约定的最早执行时刻；
- 原始概率、方向、动作和分析状态，分别保存；
- 全部实际角色模型、可获得的模型版本标识、有效提示词 hash、代码与数据快照版本；
- 记忆、信用和校准版本；
- 实验组、纳入规则、排除原因及结算状态。

真正的前向资格至少要求：预测在约定交易入场之前封存，输入截至当时可知，待预测收益区间尚未发生。历史重跑继续用于研发，但不得因为 `trade_date` 较新而转为前向样本。

若上游模型别名不能固定到模型版本，明确记为版本不可完全锁定；检测到变化后分批统计，不能假装实验条件不变。

### 2. 先统一标签语义，不把所有结果叫 T+5

本轮代码显示：

- 历史案例模块主要比较 **T+1 收盘**；
- H1b 观察指标存在 **T+5**；
- `return_labels.py` 的 horizon profile 有短线 **T+10**、中线 **T+40** 主评估点。

这些用途可以并存，但必须明示。不能用次日下跌惩罚原本预测中线改善的分析师，也不能拿 T+5 的校准映射解释 T+40。

建议建立统一结果登记接口，按报告原始事件和期限结算；收盘后定时重试，区分未到期、已到期缺数据、停牌、不可交易、已结算。**更正：回填入口不只有启动扫描**（`api/main.py:432–440`），`report_service.py:1421–1428,1778–1786` 在 completed 报告创建/更新落库后也会触发。缺的是独立、可观察的到期重试机制，不能表述为“非重启绝不回填”。

### 3. 预先固定抽样，保留所有失败和弃权

采用事前确定的股票池、抽样规则和运行时点，同时保存正常、失败、弃权和无交易机会的记录。

- 工程覆盖样本可以专门补不同角色、行业和状态；
- **绩效样本不能看了赢家、多空方向或结果以后再挑选。**

H1b 当前的平衡门槛保持原授权不变，但不要为了凑出多空均衡，筛选“想要的胜方”后拿去报告自然分布的胜率。诊断集与绩效集分开。

冻结一条稳定对照线，开发线仍可继续施工，不必让整个项目停工等待行情。若研究在线学习，冻结的是更新算法、允许使用的信息及晋升规则，而非声称系统永远不更新；每次更新都要版本化且只使用当时已成熟的结果。

**验收目标：每个进入前向成绩表的样本，都能证明预测先于结果；所有未入表样本的原因可查。**

## 四、优先级 P1：命题级复盘，而不是“亏了就写教训”

### 1. 把分析中的事实、假设和预测分开

每个关键判断挂到现有 claim/evidence 链：

- **已核验事实**：引用证据、时间、单位、原始来源；
- **分析假设**：机制解释、支持依据、竞争解释与局限；
- **待检验预测**：预期事件、发生期限、方向或概率、证伪条件。

例如“原材料降价”可以是有来源的事实；“会改善该公司的利润率”还取决于采购周期、产品降价和库存；“股价将上涨”更是另一个预测。复盘不能把这三层压成同一次涨跌判断。

守卫应继续阻止把“已被市场定价”之类缺证据判断当作事实；也应通过独立测试确认：诚实标注的假设不会仅因尚未发生而被当作数据错误。**这是需要审查的分类能力，不是本轮要求放宽现有硬闸。**

### 2. 复盘采用两次审查

第一步先不看市场结果，仅用封存的当时材料检查：论证是否成立、是否漏读反证、是否把同源消息重复计权、经理有没有忽略已核实异议。

第二步再看成熟结果：哪些预测命中，哪些未命中，有没有新事件，期限是否匹配，哪些地方仍无法归因。

这样能减轻“先看跌了，再编一个当时早该知道的解释”。复盘允许输出“无法确定”，不能把所有误差强行归为推理错误。

### 3. 不仅记错例，还要记反例和有效推理

保留至少四类：推理合理且结果有利、推理合理但结果不利、推理有缺陷但碰巧有利、推理有缺陷且结果不利。概率校准主要在多样本层面判断，单次亏损不直接判定过度自信。

每条候选经验包括适用条件、反例、证据链、观察数量、版本、可用时间及待验证的改变。检索时同时展示相似失败与相似成功，避免全是警示案例导致系统永久悲观。

经验进入历史时点的 prompt，需要满足：结果已成熟、复盘已完成、经验在当时已获准使用。不能只检查原案例的 `trade_date`。

**权限边界：复盘模块只能产出候选经验和实验建议，不直接改生产提示词、模型绑定或信用开关。**

## 五、优先级 P1：概率校准与角色信用分账

### 概率校准

现有代码 `calibration_service.py:339–398` 明确禁止 confidence 转 probability。这比聊天中的“置信度 82% 直接校准成上涨概率 64%”更严谨，应保留。

先明确概率事件：上涨、跑赢指数、或扣除成本后为正，不能互换。只有具有明确事件定义的预测数值，才有资格训练相应校准映射。

后处理校准保留原值和校准值，不抹去 LLM 原判断；仅在早期已结算样本上拟合，在之后样本上评估。少量样本先使用简单、受约束的方法，不急着切成「角色×市场状态×行业×期限」大量小格。

评价同时看：Brier/Log Loss 相对事前基准的改善、可靠性图与不确定区间、区分强弱机会的能力、覆盖率及扣成本表现。**一直报接近市场基准上涨率也可能校准良好，所以校准不是 alpha 的充分证据。**

当前 N≥30 或 H1b N≥60 是工程门槛，不等于充分统计证据。同一交易日的相关股票、重叠持有区间和重复运行不能都当独立样本；用按日期分组的配对比较和适当区块重采样估计不确定性。

### 角色信用

建议分三张账，而不是一个万能分数：

1. **证据可靠性**：引用是否真实、日期和语义是否正确；
2. **预测质量**：在其明确预测的事件及期限上表现怎样；
3. **决策贡献**：去掉这条信息或不用该经验时，整体决策是否更差。

Bull/Bear 是对抗角色，不能因为市场阶段性上涨就永久奖励 Bull、惩罚 Bear。Bear 可能提出了重要风险但仍非胜方；经理采纳也不是正确性证明。更适合评价其命题、反驳有效性及遗漏风险，并按实际角色/模型/提示词版本归档。

信用可先作为研究经理的带样本数、区间和限制说明的参考；若注入 prompt 就会影响决策，也必须作为独立实验处理，不能绕过现有 H1b 授权和门槛。

## 六、优先级 P2：用受控对照证明提升

保留原版作基线；候选每次只增加一种变化，例如「经过审查的案例提示」，而不是同时更换模型、改提示词、开信用再加校准。

- 对同一时点和同一封存证据包进行配对比较；
- 比较概率质量、净收益、风险、证据错误率、弃权率及运行成本；
- 校准仅在冻结原始输出后比较，区分收益改善来自推理、筛选还是概率重映射；
- 对随机性较大的输出，在事前确定的小批样本重复运行估计波动，不能看到不满意结果后挑重跑；
- 只在实验线做信息移除和角色消融，不删除生产功能、不改用户 3/1 轮次。

特别值得测试的问题不是“哪个 Agent 最聪明”，而是：**辩论有没有让经理采用了先前遗漏的有效证据，并因此改善之后的判断？**

反事实测试可借鉴 Profit Mirage，但它只能提供诊断证据，不能靠单一指标判定模型必定记住了未来。[3]

测试至少拆成：

- 不改变经济事实的改写/无关顺序变化：结果应相对稳定；
- 匿名实体：用来诊断参数先验依赖，变化不自动证明泄漏，匿名也可能移除了合理背景；
- 经济上自洽、确实改变关键论点的证据扰动：相关预测应出现有理由的响应；
- 无关事实扰动：不应任意跟随变化。

不能把“预测不变率越低越好”写成总目标。应该检查概率和论据如何变化，而非强迫买卖符号每次反转。

候选流程：提出假设 → 预先登记唯一主要改动及验收标准 → 历史研发 → 未来影子配对 → 审核 → 有限放行与回退。所有失败候选也登记，避免只保留最好一次。

## 七、从公开研究取什么，不取什么

- **FinCon**：取其经验反馈与有选择的角色更新思路；不把论文内收益当我们的预期盈利。[1]
- **Bridgewater 专项训练**：其 78.2%→84.7% 是金融信息筛选等六项任务的平均准确率，不是股票涨跌预测准确率。更适合启发我们建设小规模专家标注集，评测“新闻是否有用、证据是否支持结论、经理是否漏读反证”；不是立即启动昂贵的交易模型训练。[2]
- **Profit Mirage / Alpha Illusion**：取时间、反事实、成本和消融检验；不把这些论文当“LLM 分析无效”的证明，也不把匿名测试当排除污染的证书。[3][4]
- **CPCV/PBO/DSR**：可以作为后续实验方法储备，但在前向资格、标签、候选登记和样本量尚不牢固时，不优先建设全套复杂统计工具；没有一种工具能替代真实的未来验证。
- **Conformal**：不能把集合覆盖率直接当作单笔上涨概率已校准，更不能忽略金融序列的依赖和漂移条件。

## 八、补充：成本预算与样本量

### 成本按实验边界估算，不默认全链翻倍

原版与候选都完整重跑全链、且调用规模近似时，LLM 成本才接近两倍。如果候选只改经理侧经验，可以共享同一份封存的分析师输出与不受影响的上游结果，重跑改动节点及全部受其影响的下游；此时结论仅适用于该局部干预，不能冒充全链增益。纯概率后处理比较不需要额外 LLM 调用。

开跑前固定配对样本数、token/金额/时长预算、重试上限与失败处理；前向抽样必须事前确定，不按结果挑选。先从少量配对测量真实调用量和失败成本，再估算完整预算。本轮没有获取账户真实计费，故不虚报金额；不因预算修改用户角色、辩论轮次或删减生产功能。

### N 需要反推，不是再给一个万能门槛

统计功效分析需要预先定义主要指标、最小有用差异、方差/依赖结构、显著性水平和检验功效。[5] 下面由 Python 计算，仅为说明数量级，不是项目已经批准的门槛：

假设单个预先确定的检验、双侧显著性 5%、功效 80%、独立同分布样本，采用正态近似且未校正多重试验：

| 示例目标 | 近似样本量 |
|---|---:|
| 区分方向准确率 55% 与假定基准 50% | 783 |
| 区分方向准确率 60% 与假定基准 50% | 194 |
| 配对 Brier 改善 0.01，且配对差的标准差假定 0.05 | 197 对 |

50% 只是示例假设，不是 A 股天然基准；0.05 的标准差也是假设，不是实测。方向率使用两项方差的正态近似；配对均值使用 `ceil(((z_(1-alpha/2)+z_power)*sigma_delta/delta)^2)`。金融样本存在同日相关与重叠期限，不能直接把这些数字当“报告条数”；先用预先限定的试点估计配对差和日期相关性，再以日期分组/区块模拟做功效设计，并冻结正式观察期。试点仅用于设计，不作为同一候选的确认性成绩重复使用。

24 条原始 VALID 足以做工程检查和少量案例复盘，不能支撑细分角色/行业的稳定概率结论。区块重采样不能凭空增加信息，也不能靠反复看结果、达到显著即停来规避所需样本量。

## 九、建议的施工顺序和成功标准

| 顺序 | 工作包 | 完成标准 |
|---|---|---|
| 1A / 1B，并行 | 样本供给漏斗诊断 + 最小预测封存 | 区分运行失败、合理弃权、缺证据与生产契约缺陷；每条候选从产生时即可证明前向资格，不靠放宽守卫凑数 |
| 1C | 期限与自动结算闭环 | 到期独立重试；结果缺口可追踪；T+1/T+5/T+10/T+40 不混用 |
| 2 | 命题级复盘、案例与反例库 | 事实/假设/预测分离；结果盲审；经验可用时间与审批状态可追溯 |
| 3 | 校准后处理、信用分账与影子观察 | 不偷换 confidence；样本不足诚实报告；既有信用加权仍受原门槛约束 |
| 4 | 原版/候选配对前向实验与晋升 | 相同输入下量化增益和不确定性；失败候选留档；支持回退 |
| 5 | 根据证据选择专项强化 | 只针对已确认短板做数据、提示词或小任务训练，不因概念热门而加角色 |

当前首先缺稳定有效预测供给，而非仅缺未来行情；供给修复与封存必须并行。供给稳定后，真实未来结果仍需等待市场发生。测试通过、模块接通、门槛过线与“预测更好/可盈利”是不同验收结论，不能互相替代。

**最终建议：把下一阶段定义为“可验证的投研学习”，而不是“自动自我改写”。保留 LLM 的综合与辩论优势，让每次经验有来源、每次改变有对照、每次提升有未来证据。**

## 十、重试、样本身份与时间资格（18:00 前后追加复核）

### 本轮实查，不把相同标的日期自动当成重试链

真实账户近期记录中，`600036.SH / 2026-09-11` 存在两条 failed 和后来一条 completed/ABSTAIN；`000001.SZ / 2026-08-21` 同组存在两条 failed、两条 completed/ABSTAIN。相同标的与基准日不足以证明请求配置、期限、数据、模型和实验组相同，因此这些是需要追踪的重复组，不是已经核实的重试谱系，也不是已证明的数据造假或统计选择。

新报告 `959811ec3d234276be494e3e7f0279f9` 已核实：基准日 2026-09-16，created_at 为 UTC 2026-09-18 09:43:07（上海 17:43:07），状态 ABSTAIN，原因 `unadjudicated_material_claims_adopt:INV-2,INV-5`。历史重跑本身是合法研发行为；错误是把它仅凭日期分段当成真正前向证据。

### 重要时间语义纠正

`api/main.py:2987–2998` 在分析开始阶段调用 `init_report`，后者将 pending 记录的 created_at 设为当时；完成时可以更新同一 report。因此 **created_at 是记录创建时间，不等于预测完成/封存时间**。前文“生成时间”应读为“数据库记录创建时间”，不能用它单独认定预测及时完成。创建已经晚于入场时刻，可用于排除；创建早于入场，却不能证明结果也在入场前产生。updated_at 同样可能由其他更新改变。需要独立、不可回写的预测封存事件与输出 hash。

历史记录若有当时产生的可信不可变日志，可以另行核验重建时间证据；不能今天给旧记录补个时间字段就提升成已封存样本，也不能未经查证断言所有历史时间证据均永远不可恢复。

### 建议写入 P0-A / P0-B 的硬契约

以下字段为建议逻辑身份，不是已存在 schema 的声明：

1. **机会身份**：事前登记 experiment/arm、股票、信息截止时刻、预测期限、执行截止时刻、版本契约及计划重复编号。不得只靠 symbol+trade_date 去重，也不得事后按结果决定机会是否存在。
2. **尝试身份**：同一机会的每次完整尝试有 attempt_id / retry_of；节点内网络重试另外记录，不能每次 SDK 重试都新增统计样本。完整尝试次数、耗时、失败原因和成本均保留。
3. **入选规则**：在预先固定的尝试预算和截止时刻内，选择第一份完整且满足输出契约的结果，或使用另一条事前固定的确定性规则。合法 ABSTAIN 也是结果，不能因其不是 VALID 就继续抽到满意答案。网络失败、结构不完整的可重试条件事前定义。
4. **前向资格**：以被选输出实际封存时间、其全部信息可用时刻及约定入场时间判定；不能沿用第一次失败尝试的时间给后一次成功“回填资格”。成功发生在入场之后，原机会只能记超时/未形成可执行预测；若重新安排未来入场，必须作为新的前瞻机会，不得倒改旧机会。
5. **版本隔离**：更换模型、提示词、输入数据、被测代码（包括修 bug 后重跑）、依赖或影响输出的配置，不伪装成同一次纯传输重试；保存旧尝试失败，记录实际代码 SHA 与运行指纹，按预先定义的新版本/实验组规则评估。相同市场机会可以跨版本作比较，但不能以新版本成功覆盖旧版本失败，或新增一份独立市场机会计数。冻结上游输入的局部实验只能支持其干预边界内的结论，不冒充全链提升。
6. **统计分母**：运行可用率与覆盖率包含所有预先登记机会；有明确概率的预测才进入相应概率误差表，并同步披露排除数。端到端策略收益按预先定义的失败/无交易处理计算，不把失败随手填零或删除。重复尝试不得被算作独立市场机会；收益也不能挑多次输出里最有利的一次。
7. **审查场景**：至少覆盖截止前失败后成功、开始及时但完成逾期、完整 ABSTAIN 后再次请求、重试中换模型/数据、重复 completed、部分流输出、相同股票日期但不同期限/实验组。生产资格与评测分母必须一致。

### 样本量措辞补充

前述 783、194、197 是特定假设下的近似参考值，**不是数学意义上的必然下界**。相关性对方差的影响取决于方向和结构；不能从“存在相关”推出需求只能增加。Stan 的有效样本量说明也明确区分正相关与反相关的效果，但那是 MCMC 语境，不应直接移植其估计器到本项目。[7] 金融样本常见的正相关会使朴素 IID 估算偏乐观，正式需求仍须根据实际配对差、日期相关、效应大小和检验设计测算；同一模型版本本身不是必然增加误差相关的充分理由。

## 十一、定稿补充：存量证据等级、故障分层与迁移边界

### 1. 有任务身份，不等于有跨尝试的机会谱系

数据库 reports 没有单独 job_id/attempt/batch/parent/idempotency 字段，SQLite 没有 jobs 表，这两点已核实；但 `api/main.py` 多处把 `job_id` 直接作为 `report_id` 传入。因此 API 正常任务路径已有单次任务标识，并非“任务 ID 完全不存在”。同时系统有 `api/job_store.py` 的内存任务存储及可选 Redis 实现；本次没有核验当前使用哪一种，也没有读取任何 Redis 凭据或内容。

真正欠缺的是跨尝试的稳定机会关联，以及将尝试、输入/代码版本、时间资格与选样规则联系起来的可审计记录。

存量审计划分为三档，不一概宣称“原理上只能启发式”：

- **已证实关联**：有当时可信的请求日志、任务映射、批次清单等，能够明确连接原任务与重试。依据原证据重建，不覆盖原始记录。
- **疑似关联**：仅同股票、日期、时间邻近或相似报错。只能做排查聚类，不能据此合并正式样本或认证前向资格。
- **无法关联**：证据不足，明确 unknown，不补造 parent/attempt/opportunity 关系。

逐条已存在的报错、创建时间和状态仍然是实测事实，不因为缺少机会关系而都变成“启发式”。反过来，也不能因为单次任务 ID 存在就宣称机会谱系已齐全。

### 2. 失败要拆“发生层级”和“原因”，不能相互排斥地混分

2026-09-18 18:12 上海时间只读快照：全库 failed 共 742。按公开的临时规则“先归 Horizon 外层包装，再匹配显式/文本 5xx，最后剩余”得到：

| 临时互斥桶 | 数量 |
|---|---:|
| Horizon 外层包装 | 195 |
| 未被前项覆盖的 5xx 文本 | 137 |
| 剩余 | 410 |

总数已程序校验为 742。与 Claude 给出的 195/138/409 有细微差别，不能猜测一定由时点变化造成；未取得其分类规则前，不宣布复现了其分类。忽略外层包装作重叠匹配时，5xx 文本共 249，说明它与 Horizon 类存在重叠。“Horizon analysis failed”仅是出错层级，不是根因。

剩余 410 中，395 条带中断/恢复标记，主要是：214 条“分析任务已中断，请重新发起分析”、178 条“进程中断，启动恢复流程标记”、其余 3 条恢复/重启文案。余下 15 条需继续按证据分类。这证明“其他”大部分已有可解释的生命周期标记，不代表已经知道进程为什么中断，也不能把批量恢复标记数当成同等数量的独立服务崩溃。

P0-A 首项交付应为双轴失败台账：发生阶段、外层包装、原始错误/HTTP 状态、可重试性、实际版本、证据位置、根因确认度；保留 unknown。审计不得凭分类规则的先后顺序，让上游错误在不同表中消失。

`'str' object has no attribute 'get'` 是类型/结构访问错误的信号，但只凭包装后的字符串不能绝对定位本地或上游。当前主线 `4b540b0` 确有研究经理 non-mapping excluded_evidence 的防护修复；若要把具体失败行归到该缺陷，仍需对齐当时运行 SHA、堆栈或可复现输入，而非由错误词直接认定。确定属于代码缺陷且已经改代码后，新运行属于新被测版本，不是纯网络重试。

### 3. 配对相关与样本间聚类分开估计

令同一机会两臂指标差为 d，则 `Var(d)=Var(X_candidate)+Var(X_baseline)-2Cov(X_candidate,X_baseline)`。在两臂边际方差固定时，配对内正相关降低差值方差；不同机会之间（同日、重叠期限等）的正相关可能提高平均差的不确定性。正式功效设计同时考虑这两个层次，不能使用一句“相关性令需求只增不减”。已有 Brier 样本量例子使用的是“差值标准差”，不能再重复扣除一次配对带来的收益。

### 4. 迁移/回滚属于独立放行事项

本文可以作为需求约束基线，不是 schema 变更、生产写库或部署授权。后续 P0-B 设计应先证明哪些已有字段/存储可以复用，必要时才设计新增 schema，并独立说明：备份、旧读写兼容、原记录不覆盖、幂等写入、并发约束、旧数据 unknown 状态、验证与回滚。回滚不得删除已封存预测或静默恢复旧的宽松前向判定。无可信旧证据的记录不能在迁移时自动补为“已封存/真前向”。
