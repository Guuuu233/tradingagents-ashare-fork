# TradingAgents：对 Fable / GPT 学习方案的评议

核查时间：2026-09-21（本机 UTC+8）。本文件是研究建议，不是代码修改、改模型绑定、数据库迁移或部署授权。

已读用户粘贴的 Fable 建议及完整 GPT 附件。只读检查当前代码与 `/healthz`：宿主 HEAD 与线上代码均为 `8a5b1bffb10eedb125d23bb0b060359bf0887337`。本轮不把 9 月 18 日样本数量、故障状态和任务进度当成当前事实；没有调用真实分析、没有跑全量测试、没有修改产品或生产数据。

## 一、结论

保留 TradingAgents 主链，增加基率、命题记忆、市场状态和外部验证的方向可以采纳。但应将“值得验证的机制”与“已经证明能提高准确率”分开。当前没有证据支持为本项目承诺“在30%样本上达到62%”，也没有同条件实验支持把预期差、基率、记忆的效果大小排出确定名次。

建议将下一阶段分成两条线：

- **可信度线**：有效供给、机会/尝试身份、预测封存、正确期限与结果账本、校准和选择性预测评估。
- **分析增量线**：预期基线供给、窄范围基率工具、命题记忆；先影子比较再接入决策。

不是为了验证而停止研究，也不是因为新概念多就一口气建多个独立引擎。

## 二、当前已有基础，不应重复建设

| 建议 | 当前只读代码证据 | 真正增量 |

| 市场状态 | data_collector 已有量价状态；evaluation_schemas 已有 market_regime 与分组统计 | 建立共享、可复现、只用当时数据的状态特征；已有字段不等于已完成全市场状态引擎 |
| 历史案例 | historical_cases 已按标的/行业检索并保存 T+1 结果 | 按可检验命题及机制检索，增加状态历史、反例和结果可知时间 |

代码存在不等于生产数据充分或实证效果成立，本轮未为上述新能力做完整运行验收。

## 三、预期差：应成为提问框架，不宜成为一刀切淘汰门

应要求重大定价论点说明：相对什么预期？依据是什么？市场可能漏看什么？何时验证？

但“没有预期差就判论点无效”不应直接实施。它会把以下情形混在一起：

1. 有可信事前预期，且与实际可比；
2. 只有公司指引、单家券商估计或模型情景；
3. 无法观测市场预期，但存在需要记录的真实事件或风险。

只有第一类才能严格声称“相对该共识的超预期”；第二类须标明基线类型，第三类保持 unknown，不编造数值，也不因此自动否定全部研究价值。价格上涨或估值偏高不能单独证明某项消息已经完全计入价格。

在当前 `fundamentals_analyst.py:332–343`，缺基线时已走 qualitative/gap，数值留空；这应保留。合理假设可以接受反驳，但不能升级成已核验事实。此前守卫误报的教训意味着新增任何硬门都必须同时验证“挡住无证据断言”和“放过正确的不确定/条件/否定表述”。

### 真实数据可行性

Tushare 官方 `report_rc` 文档列有研报日期、机构、预测期间和盈利预测值，也单列 TS 更新时间。[5] 它可作为候选原料，不是已经验证的本账户权限或完整 PIT 共识库。本轮未调用付费接口、不改 Token、不购买权限。

合成参考共识时应：同预测期间/指标/单位对齐；同机构去重并保留修订；仅使用事件发布前可知版本；明确贡献机构数、估计分散度、陈旧程度与覆盖率。`report_date` 不等于盘中实际可见时刻，数据库更新时间也不能冒充首次可知时间。公司预告、卖方预测和市场隐含预期不得混称。

## 四、基率工具：本轮最值得优先做的小实验

它的价值是让模型对“相似情形通常如何”有客观参照，而不是给每个观点配一个看似科学的百分比。

### 应建在市场事件样本上，而非只在系统成功报告上

分清两种样本：

- **市场基率**：事前定义的股票池中，客观事件发生后结果如何；可使用合规的历史市场数据。
- **模型校准/能力**：本系统当时实际封存了什么预测，之后结果如何。

前者不必等本系统积累大量报告；后者不能借市场事件数量充作模型经验。市场库也不意味着无泄漏：事件特征须当时可知，后续标签须在查询时已经成熟，并保留退市/停牌/缺数据等样本处置。

### 第一版建议范围

只选择一个有真实字段支持的事件类型和一个既有期限；事件定义、股票池、基准和查询规则预先冻结。先让工具影子输出，不强制所有 Bull/Bear 论点必须引用。

返回内容至少包括：条件定义、查询 as-of、原始事件数、不同股票/日期数、纳入排除原因、结果覆盖、事件率/收益分布与不确定区间、是否退回更宽条件，以及查询版本。

**LLM 不能反复改筛选条件直到找到支持自己的一组概率。** 条件不足时依照固定层级回退到更广泛基率，或明确不可估计；记录全部查询，不只保留被引用的有利结果。

基率仅是统计关联，既不证明因果，也不能单独验证“已经定价”。正文中的 N=284、53.1% 等是对话示例，不是本项目结果。

## 五、Thesis Memory：把一个故事拆成可分别结算的命题

“AI服务器需求推动PCB高阶化”可以作为命题家族标题，但不能直接被未来涨跌验证为真。

应拆成例如：

- 需求命题：指定订单/出货指标是否在期限内变化；
- 经营命题：指定 ASP、毛利率或库存指标是否变化；
- 定价命题：指定可执行区间的股票相对收益是否达到定义条件。

每个命题保留证据、反命题、可测量判据、期限、状态及修订原因。经营预测正确、股价判断错误时分别结算，不能以盈利证明因果叙事正确。

状态可包括候选、观察中、部分支持、被反驳、到期未验证、证据不足；active 只能表示当前跟踪，不能表示已证明正确。复盘仍先盲结果审查当时论证，再看成熟结果。保质期意味着降级或暂停引用，不是删除不利历史。

检索资格至少同时检查案例/结果/经验在当时是否可知；只比较原案例 trade_date 不足。原生报告和全部状态转换应保留，版本变更不得覆盖历史判断。

## 六、预测目标：增量加入相对基准，不删除绝对收益

接受 GPT 的多目标方向，但建议分阶段：保留当前绝对收益诊断，先影子增加一个事前固定的相对基准目标；其余风险概率和收益幅度只在可定义、可结算、可验证时增加。

注意：

- 股票收益减指数收益是基准相对收益，**不是自动剥离 beta 后的 alpha**。若研究风险调整 alpha，需另外定义因子模型与仅用当时数据估计的风险暴露。
- 沪深300与行业指数承担不同问题，基准事前固定，不能事后挑容易跑赢的那个；行业归属也必须有历史时点依据。
- 输入、入场/出场、交易成本、分红/复权口径须对齐；研究指数比较与真实可交易基准成本分开。
- 每个概率对应独立事件和校准账，不能把 BUY 置信度复制成上涨、跑赢行业、回撤风险等多个概率。
- 跑赢基准也可能绝对亏损；高命中率若伴随大额尾部损失，未必更有投资价值。只凭“30%覆盖下63%正确”不能认定优于另一策略。
- 把握度不直接决定仓位，仍需收益/损失幅度、尾部风险、相关性、流动性和成本约束。本轮不改仓位决策。

## 七、校准和弃权：有研究基础，但没有固定收益保证

SelectiveNet 的研究支持用 risk–coverage 关系评价选择性预测；其分类/回归基准结果不能直接推出我们的 A 股系统必能达到某个命中率。[2]

应拆分：运行失败、证据不足/违规阻断、分析完整但没有足够优势、交易条件未满足。它们不是同一种“学会不做”。不能把程序误拦或数据接口缺失记成聪明弃权，也不能把合理 WAIT 改成 BUY 以填合格池。

选择阈值只在开发/验证段确定，未来固定使用并报告覆盖率、绝对和相对基准误差、经济结果、缺失和失败数。全量/条件分母并列，避免只报选中的漂亮部分。

校准不是低样本万能解法。官方文档明确提醒 isotonic 在小样本下容易过拟合；使用何种方法应由数据和时间隔离验证决定，不保证“百级就够”。此外，Brier 同时反映可靠性、区分能力及结果不确定性，Brier 降低不自动表示纯校准改善。[1]

单纯单调校准通常不增加排序信息，但可以通过阈值和仓位影响经济结果；“不会创造 alpha”宜作对信息增量的提醒，而非对所有后处理收益效果的绝对断言。当前项目 confidence 与 probability 的隔离继续保留。

## 八、Regime、能力地图与多模型一致性：先观察，后干预

### Regime

优先共享当时可计算的趋势、波动、宽度和流动性特征，标签只作压缩摘要。阈值及拟合只用过去数据，不用全历史分位或事后平滑给过去贴“牛市/熊市”。样本不足时不切大量子组；可以先作描述性诊断，不急于影响信用或路由。

### Expertise Map

可在角色、预测对象、期限和版本上描述哪里有证据更可靠，但必须标样本数和区间，不把“经理采纳”当真值。改变信息供给或路由后，数据分布也会变；观察图谱和自动信用调整分开验收。它更像条件绩效档案，不必先包装成复杂元学习系统。

### 重复运行与异构模型

重复运行衡量输出稳定性，不等于客观正确概率；模型可以稳定地犯错。不同模型也可能共享训练资料、来源或同一偏差，辩论后更不是独立意见。

特别是“Claude做Bull、GPT做Bear”混合了模型差异与职责提示差异，不能据此认定哪家模型更可靠。若研究模型差异，在实验线固定同一个任务/角色、同一封存输入，做配对或角色交叉对照；测独立观点时应在互看输出之前封存。正式用户绑定和轮次不改，不采用“人多/模型多就加票”。先小批测重复性，不默认全链反复运行。

## 九、RL：现阶段不做，不把评分表误叫训练算法

Fable 关于“收益 RL 几千回合几乎必然只学 beta/动量”的断言没有充分依据；具体样本需求和结果取决于环境、策略、奖励及训练方式。但本项目当前确实没有必要优先开展端到端收益 RL。

过程监督在数学任务有实证支持，不能直接迁移为金融盈利保证。[6] 另有编码环境研究显示，把过程监控纳入奖励也可能被优化成隐藏的 reward hacking，说明过程奖励并非天然安全。[4]

暂时不采用任意加权的 `过程分 + 预测分 + 校准分 + 收益分` 总奖励：

- Brier/LogLoss 是损失，若进奖励须明确反向；Brier 与单列 calibration 可能重复计量；
- 格式完整、引文数量和跨次一致性都能被迎合，不能替代实际有效证据；
- 数据泄漏、编造证据等不可用较高收益分抵消；
- 校准是多样本统计性质，不是每个单例都能独立给一个“校准奖励”。

更合适的是：不可补偿的真实性/时间硬约束 → 单独的过程质量评测 → 明确事件的样本外预测评分 → 独立的经济验收。先记录这些维度，不立即自动改变生产策略。以后有可靠专家标签，再从证据支持判别等窄任务训练做起；“几百到几千条”不是跨任务通用的充分样本保证。

## 十、推荐的有限范围下一步

| 层次 | 保留/新增内容 | 是否立即改变生产判断 |
|---|---|---|
| 原P0 | 供给诊断、机会/尝试身份、封存与正确结算 | 只修被证实缺陷；不放宽守卫 |
| 小型能力试验 | 年度首次业绩预告区间相对事前同年度、同口径卖方预测＋命题档案 | 先做可比性/版本/覆盖核验，再影子；不混快报 |
| 基线补强 | 事前预期来源/期间/版本资格，与现有 E-04 对接 | 经独立审查和同输入对照后再接入 |
| 早期评价与候选学习 | 一个新增相对行业基准目标；校准与选择性预测同批 | 可先拟合候选阈值与作risk–coverage诊断；样本不足不启用选择器 |
| 早期输入试验 | 复用已有特征的趋势/波动/宽度摘要 | 先影子存档、同输入对照；不自动改信用、路由 |
| 后续 | 市场状态条件化的能力地图、局部经验注入 | 有样本和增益证据后才干预 |
| 暂缓 | 收益 RL、自动改提示词、自动改角色路由、全链多次采样 | 不实施 |

选择实验事件时先按数据覆盖与可复现性决定，不能先选“历史最好看”的事件。保留稳定对照，逐项增加，实测收益不预先保证。

**最终结论：应采纳的是“有数据支撑的预期比较＋基率参考＋可证伪命题记忆”，不是“更多必须填满的字段、更多能把报告挡掉的门”。让系统能承认未知、保留假设并接受未来验证，比强迫每份报告输出一套看似专业的精确数字更重要。**

## 十一、Fable 回应后的首个事件边界

### 接受两项提前，但区分观察与生产干预

**选择性预测与校准同批推进。** 建立风险—覆盖率诊断、尝试简单候选选择规则都可以较早做；“粗分几桶看看”是探索，不是已证实某行业/状态无优势。样本需求不能不经效应量和方差测算就声称必然小于能力地图。阈值只在开发/验证期确定；影子前向验证后才改变生产选择。代码误拦、数据拒绝、运行失败仍不算模型学会弃权。

**市场状态作为输入可提前试验。** 趋势和波动可能复用已有行情，宽度仍需要当时股票池、停牌/上市状态及有效分母。标签计算成本可低，但不是零成本；输入 prompt 就是决策干预。先保存连续指标、计算窗口、as-of、缺口与算法版本，再用稳定摘要做影子对照。不等待信用样本积累，也不未经测试直接全角色生产注入。阈值、标准化和任何拟合都仅用过去数据。

### 首个事件建议定为年度首次业绩预告，快报暂不混入

建议研究对象：**年度首次业绩预告区间，相对公告前可知的同年度、同净利润定义的卖方预测。** 年度是为了减少年度券商预测与季度/半年累计公告错配，不是证明年度事件收益最好。首次预告与更正预告分层，快报为另一事件类型，不能一次混成“预告/快报”的统一实际值。

业绩预告是管理层预计区间，不是已实现利润；快报是初步业绩，不能默认等同最终审计数字。Tushare 文档显示 forecast 包含预告区间、公告日和首次公告日；express 包含公告日、初步数值及 is_audit。[7][8]

### “PIT 天然成立”不成立

官方字段表中 forecast/express 给的是公告日期，report_rc 给的是研报日期及 TS 更新时间，不能直接证明盘中先后、首次可见版本和完整修订史。forecast 文档写每日20–21点更新，report_rc 写每晚19–22点更新，进一步说明公告日期与供应商实际可用时间不能混为一谈。[5][7][8]

- 不能把当前修订后的预告区间贴到 first_ann_date，冒充最早版本。
- 同日券商研报可能已看到预告。若拿不到可证实的盘中先后，事件比较基线保守排除同日研报，且保留日期精度限制；排除同日不自动解决数据后改问题。
- 共识只用事前可知记录，每机构按事前规则取最新有效估计，记录机构数、陈旧度和分散度；同报告多作者不能多计票。
- 净利润归属口径、扣非与非扣非、币种、年度/累计/单季、单位必须逐项核实。forecast 为万元、express 净利润为元，report_rc 预测净利润为万元；不能直接连接同名字段。[5][7][8]
- 缺点时数据、初版证明或同口径预测时，保持不可比较/替代基线。不得以“接口存在”证明有数千合格独立事件。

### 区间比较优先于伪精确“超预期百分比”

保留预告上下限及固定规则生成的卖方参考值/分布，区分区间整体偏上、整体偏下、覆盖参考值、不可比较。预告中点若使用，只是事前约定的摘要，不是实际利润或天然期望值。亏损、扭亏或接近零的基线不能套普通百分比；不把同比增幅当预期差。分类阈值需在看结果之前固定。

### 一个影子主目标、一个主期限

保留当前绝对方向诊断，新增“同一可执行入场—出场区间，个股收益是否超过事前固定的行业指数收益”的影子概率目标。行业体系、指数版本与历史归属固定，缺失不能悄悄换沪深300，也不能用今天行业标签套过去。

主期限建议复用当前短线 profile 的主评价 T+10（`horizon_profile.py:27–42`），而非同时新增 T+5/T+20。实施前将现有 profile 的信号日、T+1 Open 入场、T+10 结算锚点逐一对齐；本建议不把“入场后十天”自动视为“信号日T+10”，也不修改现有期限。其他期限可以后单独预注册，不按回测最好结果选择。

公告日是事件索引，不自动是可交易T0。事件实际可用、所需行情齐备、预测封存完成都必须早于约定入场。对只有日期级时间的历史资料，可以采用明确保守的日频锚点研究，但不能宣称精确盘中PIT，更不能用延迟入场掩盖初版不可恢复。停牌、涨跌停不可成交和延迟观察保留记录，规则事前固定。

事件后首段跳空属于事件响应研究，不等于系统能在消息出现前买到；基率研究收益窗口必须与模型预测窗口一致。

### 第一张工作包是覆盖与可比性核验，不是立即训练

不等待历史模型样本，但先取得下列产物：

1. 在事前固定期间和股票范围内，核对事件数据、卖方预测、历史行业指数及价格的真实权限/覆盖；不选赢家、不先看收益筛事件。
2. 输出原始事件 → 首次年度预告 → 初版/时间可核验 → 同期同口径基线 → 行业与价格可结算的逐层计数及缺口；正式需要的机构数和陈旧窗口等规则在检验收益前登记。
3. 保留每个阶段的原文/原始快照和来源，证明更正预告没有覆盖初版。数据源无法提供时明确限制，不能为了闭环填造。
4. 首先做简单条件基率，不立即构造“超预期幅度×估值分位×前期涨幅”的细网格。估值必须使用事件前可知盈利，亏损PE单独处理，前期涨幅不得包含事件后的跳空。
5. 业绩披露事件池不能冒充全A股随机样本；结论先限于所覆盖的披露和研报覆盖公司。保留无共识/无行业/退市/停牌样本的计数，不把缺失当不存在。
6. H17 只登记为候选假设，同时保留零效应与相反机制（信息继续扩散）的可能；后续公告和重叠事件记录为事件历史，不因看到不利结果事后删样本。

上述核验通过后，再对同一封存输入比较“现有链”与“增加固定基率提示的链”。先不把基率注入信用权重；题目本身即使没有显示出预测改善，也保留负结果。

### 术语与范围补充

反复改查询条件寻找支持自己的结果，主要是选择偏差/多重尝试问题；只有条件选择或统计数据用到了预测时不可知的信息，才同时构成前视，二者不应混称。

“高价值/分歧样本按需重复运行”也须事先定义触发条件和次数、在结果发生前触发，并记录全部输出；它可以诊断稳定性，但不是随意重抽直到满意。局部调用率/成本与全量效果分别报告。

首个事件与主目标可以按以上范围进入研究设计；本轮仅核查公开文档与本地期限源码，未实调账户接口、未确认最终样本数、未新增数据库schema、未派发生产施工。
