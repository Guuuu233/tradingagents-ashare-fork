## 1. manifest.json 一致性（全量 22 756 条）

核对方法：逐条比对 `files` 键 → `api_cache/<file>` 存在性、字节数、必备字段；
对确定样本复算 `sha256`（分块读取，单文件不占满内存）；按 api 分层抽样
重载 pkl 核对 `rows`。

| api              | manifest 条数 | manifest rows 合计 | fetched_at 区间           |
| ---------------- | ------------: | -----------------: | ------------------------- |
| trade_cal        |             3 |             18 946 | 10-05 06:48:20 → 19:06:44 |
| stock_basic      |             3 |              5 911 | 06:48:32 → 06:48:34       |
| index_classify   |             1 |                 31 | 06:48:35                  |
| namechange       |             1 |             34 755 | 06:48:44                  |
| sw_daily         |            31 |             77 221 | 06:48:46 → 06:49:31       |
| index_weight     |             2 |            120 614 | 06:49:54 → 06:50:12       |
| daily            |         2 491 |         10 371 853 | 06:50:13 → 08:08:03       |
| daily_basic      |         2 491 |         10 284 102 | 08:08:06 → 09:39:03       |
| index_member_all |        11 822 |              7 915 | 09:39:04 → 15:33:35       |
| adj_factor       |         5 911 |         19 095 730 | 15:35:10 → 18:51:30       |

- 文件存在性 / 零字节 / 必备字段：**0 缺失、0 零字节、0 缺字段**（22 756/22 756）。
- `sha256` 核对分两层：
  - `api_cache/` 内 22 756 个文件（manifest 覆盖范围）均为小文件
    （单文件 < 数 MB），脚本按种子确定性抽 5 条复算，全部一致
    （`sha256_bad` 为空）；`manifest["files"]` 中并不存在 >50 MB 的
    条目，v1 报告「抽 5 大 + 5 小」表述不成立，已更正。
  - 缓存根目录三个合并大文件 `daily_all.pkl`（736 MB）/
    `daily_basic_all.pkl`（648 MB）/`adj_factor_all.pkl`（592 MB）
    不在 manifest 内，脚本以 chunked `sha256` 实测并将摘要写入
    details JSON（复算口径与该行数对账一致：`daily` 10 371 853 行、
    `daily_basic` 10 284 102 行、`adj_factor` 19 095 730 行 = 分块
    合计）。
- `rows` 抽查：每 api 抽 25 条重载 pkl 比对行数，共 135 条，全部一致。
- `fetched_at` 均在 2026-10-05 同一抓取窗口内，时序合理（daily →
  daily_basic → index_member_all → adj_factor 顺序推进）。

### 2.5 index_member_all（行业归属）

- `index_member_all/` 目录 5 911 个文件 = stock_basic 全集；manifest
  Y/N 两批各 5 911 条，无缺失。
- `index_member_all_all.pkl` 7 915 行、5 909 个 symbol；`is_new`
  Y=5 909 / N=2 006；Y 批 `rows=0` 的两只（000765.SZ、T600018.SH）均为
  窗口前退市股，目录中为 0 行空表，一致。
- **字段语义（Tushare `index_member_all` 文档）**：`is_new='Y'` 为当前在属，
  `out_date` 以**空串**作哨兵（实测 Y 批 5 909/5 909 全部 `out_date==''`）；
  `is_new='N'` 为历史区间，`in_date`/`out_date` 均为实际日期（实测 N 批
  2 006/2 006 `out_date` 非空）。v1 曾把 N 批 `out_date` 误读为「全空」，
  本版更正。
- **PIT 归属可还原**：5 909 个 symbol 的 Y+N 区间拼接后，多区间样本
  （1 646 只）`in_date`/`out_date` 链式衔接、0 重叠，可从上市日连续
  覆盖至期末；单区间样本（4 263 只）仅 Y 行，`in_date`=上市日、
  `out_date`='' 亦连续。**故不存在「只能用现属、有前视偏差」的结构性
  缺陷**——`in_date`+`out_date` 已足以还原当时归属。
- **残留缺陷（DAV-1446 的本体）**：`index_member_all_all.pkl` 无
  `con_code` 列；Y/N 两批**未在缓存层拼接**成统一区间表，下游须自行
  `concat` + 按 `in_date` 排序才能得到 PIT 序列；2 只退市股 0 行（同 §2.4
  `T600018.SH`/`000765.SZ`）。这些是「未加工成即用 PIT 表」的形态问题，
  不是数据缺失。

## 3. 缺口清单

按「阻塞 P1 后续研究」vs「可容忍局限」区分：

| #   | 项                                                                                                  | 判定        | 说明                                                                                                                                                                                                                                                                                                                                                        |
| --- | --------------------------------------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `index_member_all_all.pkl` 无 `con_code` 列，且 Y/N 两批未在缓存层拼接为统一区间表（DAV-1446 本体） | **阻塞 P1** | `in_date`+`out_date` 足以还原 PIT（N 批 `out_date` 为退出日、Y 批空串=在属），但缓存里两者是**分开的两份记录**，下游须自行 `concat`+排序才能得到完整区间；同时缺 `con_code` 列（Tushare 原接口本应返回，DAV-1446 的实质）。建议另开补抓/加工卡：要么要求上游补齐 `con_code`，要么在下游加工层把 Y/N 拼接、补齐 `out_date` 哨兵为空值，量级为一次性加工不涉及重抓。 |
| 2   | `T600018.SH` `adj_factor` 0 行、`index_member_all` Y 批 0 行                                        | 可容忍      | 2006 年退市股，窗口内无交易日；P1 股票池本就不含它。                                                                                                                                                                                                                                                                                                          |
| 3   | `000765.SZ` `index_member_all` Y 批 0 行                                                            | 可容忍      | 2005 年退市，同 #2。                                                                                                                                                                                                                                                                                                                                        |
| 4   | 000022.SZ / 000043.SZ / 300114.SZ 不在 `stock_basic`                                                | 可容忍      | 更名/借壳复用 ts_code；可由 `namechange` 衔接，P1 股票池规则已按 `ts_code`+可交易日过滤。                                                                                                                                                                                                                                                                   |
| 5   | `daily_basic` 每日行数 < `daily`                                                                    | 可容忍      | 停牌/新股当日无估值的正常差异，非缺日。                                                                                                                                                                                                                                                                                                                       |

未发现缺文件、缺日期、缺行业、行数对不上的硬缺口；唯一结构性项是 #1
的「Y/N 未拼接 + 缺 `con_code`」，PIT 归属本身可由 `in_date`/`out_date`
还原。

## 4. 验收结论

**缓存满足 P1 分块构建与 T+40 研究的最低需求**：交易日历、按日分块
daily/daily_basic 连续无缺（2 491/2 491 日），sw_daily 31 行业齐全，
adj_factor 与 index_member_all 覆盖全部 5 911 只标的并与 manifest
一致，指数权重月度快照齐全。PIT 行业归属可由 `in_date`+`out_date`
完整还原——`is_new='N'` 行携带真实退出日、`is_new='Y'` 行以空串示
在属，多区间样本链式衔接无重叠（§2.5 实测）。残留项仅 #1：Y/N
两批未预拼接 + 缺 `con_code` 列，属「待加工形态」而非数据缺失，
不阻塞 P1 开工，但下游需先做 Y/N 拼接加工；正式 PIT 归属口径裁定
仍属 DAV-1453。
