## 目标
为 LLM 客户端增加"瞬时错误重试"：网络抖动/上游 500/EOF/限流等瞬时故障时自动重试 1~2 次，避免一次抖动导致整个分析失败；正常完成的调用不重试（保持"不重复扣费"原则）。

## 背景（David 实测反馈 2026-08-07）
- 分析中途失败："Error code: 500 - {'error': {'message': 'Post https://opencode.ai/zen/go/v1/chat/completions: EOF'}}"，整个 dual-horizon 分析（~25 分钟）白跑
- 实测：故障约几分钟后上游自动恢复（三次调用全 200），属瞬时故障
- 现有配置：`tradingagents/llm_clients/openai_client.py:88-89` `max_retries = 0`（注释：禁用一切重试，避免 Thinking 模型重复扣费或因重连导致的状态丢失）——副作用：上游抖动 1 秒即全盘失败

## 修复要求
1. **仅对瞬时/可重试错误重试**（建议 1~2 次，指数退避或固定短延迟 1-2s）：
   - 网络层：ConnectionError / EOF / ReadTimeout / APIConnectionError / 上游 5xx（500/502/503）
   - 限流 429（注意 429 可能也是配额耗尽——重试 1 次即可，仍失败显式报错）
2. **不可重试的错误直接失败**：401/403（认证）、400（参数错误）、404（模型不存在）、内容审查类错误——重试无意义，避免浪费
3. **保持原则**：正常完成的调用零重试；重试只发生在"请求根本没有成功响应"的瞬时故障上，不因重试导致同一成功请求重复扣费（只有失败才重试）
4. 覆盖所有 LLM 调用路径：OpenAIClient 主路径（invoke/astream 流式注意：**流式请求中途断连**已有处理逻辑，不要破坏；新增重试只针对"流建立前失败"或按现有流式重试语义）——实现前先读 `openai_client.py` 全文和调用点，确认流式/非流式两条路径的现状再动手
5. 配置化：可用环境变量（如 `TA_LLM_RETRY_TIMES`，默认 1~2）控制，不硬编码
6. 关注多模型并发场景：重试不要引入同角色并发重复调用（锁/幂等语义保持现状）

## 测试要求（TDD）
- 模拟上游瞬时 500 后成功 → 断言重试后成功且调用次数 = 1+重试数
- 模拟持续 500 → 断言最终失败且调用次数 = 1+重试数（不无限重试）
- 模拟 401 → 断言不重试（1 次即失败）
- 流式路径：模拟流中途断连 → 行为不回归（现有测试全过）
- 全量回归 0 新增失败

## 验收标准
- 瞬时故障自动恢复（重试成功）；持续故障快速失败（不无限重试）；认证类错误不重试
- 现有 LLM 相关测试全绿；全量回归 0 新增失败
- 完成后评论汇报（改动文件、重试策略、测试结果），等 Hermes 验收
