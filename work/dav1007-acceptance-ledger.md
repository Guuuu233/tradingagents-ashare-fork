## 下一轮技术口径修正（覆盖之前的建议）

❌ **作废**：「观察/deny 记录里保留实际解析/连接目标」。
原因：audit hook 触发在连接发生**之前**，通常只能可靠记录**调用方传入的地址**；
在 hook 里额外做 DNS 解析反而会**制造新的外连并污染证据**。

✅ **改用时间相关法区分「漏拦」与「hook 安装前遗留」**：

1. hook 安装完成、测试启动**之前**，立即记录一次**进程树网络基线快照**
2. 每次 `lsof` 采样记录 **PID、时间、远端 IP、连接状态**
3. observer/deny 继续只记 **PID、nodeid、阶段、主机名、时间**，**不做解析**
4. 若**基线为零**、运行后才出现 ESTABLISHED → 按**时间先后**排除「安装前遗留」
5. **无法配对的连接一律判失败**，不得默认解释成「遗留」
6. **子进程必须单独证明装了护栏**，否则结论只能限定为覆盖主进程

## SHA 谱系表述纪律（易错）

**「直接父」与「累计审查基线」是两个不同概念，报告必须分开写。**

- **直接父**：取决于提交方式，**不得预先写死**
  - `amend` 旧候选 → 新 SHA 的直接父**不变**
  - 另加修复提交 → 新 SHA 的直接父**是旧候选**
  - 交付时用最终 SHA **实测**：`git log -1 --pretty=%P <最终SHA>`
- **累计审查基线**：始终是 `5a0320f`，用于 `git diff --name-only 5a0320f..<最终SHA>`

❌ 反例（2026-09-16）：调度评论称「直接父：5a0320f」，实测为 `2f5fa28`（链路 `5a0320f → 2f5fa28 → 2ae1fed`）。

## 工作树冻结纪律（证据绑定的前提）

⚠️ **SHA 不变不等于源码不变。** 工作树被改过，测试跑的就是**混合内容**，证据同样失效。

| 时机 | 要求 |
|---|---|
| **开跑前** | `git status --porcelain --untracked-files=all` **输出为空**；连同 `git rev-parse HEAD` 一起记入报告 |
| **运行期间** | **禁止修改/生成/替换仓库内任何文件** —— 不改代码、不写报告、不落日志到仓库内、不生成临时脚本；日志与采样一律写仓库外唯一路径 |
| **结束后** | **再次**确认 `git status --porcelain --untracked-files=all` 仍为空，且 `HEAD` **仍等于锁定 SHA**；两次快照都进报告 |

✅ **最稳妥做法**：用 `git worktree` 在**锁定 SHA 的独立干净工作树**中运行，与开发工作树物理隔离。

实务提醒：`--untracked-files=all` **不显示 `.gitignore` 忽略的文件**，
故 `__pycache__` / `.pytest_cache` 不会让它变非空，属正常——
**不要在跑测中途去删缓存**，那本身就是「运行期间修改仓库内文件」。
