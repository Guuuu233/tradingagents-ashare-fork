## 核心要求

### 0. 算法代际/产品差异（当前专项工作假设）

用户对照发现：新浪财经 Web 测试版很可能沿用古老资金分类算法，而新浪财经客户端、同花顺、东方财富使用较新的资金分类算法；这能解释 Web `+5160.77 万` 与客户端/东财/同花顺大额流出结果的巨大差异。该判断作为当前专项的工作假设，团队必须用页面标签、接口字段、请求时间和受控样本验证并记录，不得把“算法不同”当作未经验证的最终事实。

因此：
- Web、App、东方财富、同花顺先按“产品/算法族”分组，不做跨代际原始数值平均；
- **算法代际冲突时明确优先级：优先采用客户端/当前算法平台（新浪 App、东方财富、同花顺等）的数据；不能因为新旧算法组间差值大就输出“主力资金无法判断”；**
- 在当前算法族内部做可比性与离散度检查，形成新算法组共识后作为主结论；
- Web 旧算法只作为独立历史参考，明确标注 `legacy_web_algorithm`，不得覆盖新算法组结论；
- 若无法确认算法代际或字段映射，保留各平台结果并标记“算法/口径冲突”，不强行排除任何源。

### 1. 多源优先级与抓取

优先尝试独立平台：
1. 东方财富个股资金流；
2. 同花顺/同花顺富耀可用的个股资金流或可比分类；
3. 新浪财经 App/移动端口径（若能定位真实 endpoint）；
4. 新浪财经 Web 仅作为补充，不得单独决定主力方向。

每次必须保存：股票代码/市场、分析基准日、数据日期、抓取时间（含时区）、平台、endpoint、原始字段、单位、字段映射、原始 JSON/脱敏快照、status/error。

### 2. 可比性检查

不得仅因字段同名就合并。合并前检查：
- 同一股票、同一交易日、同一收盘/盘中时点；
- 元/万元/亿元单位统一；
- 总净额、特大单、大单、中单、小单、主力的定义和分类阈值；
- 统计的是单日还是 3/5/10 日累计；
- 是否是实时快照、收盘汇总、历史日线；
- 股票代码和市场后缀没有错位。

### 3. 离散度与离群源规则

对可比字段做跨源统计：
- 每个平台先得到同一字段、同一日期、同一窗口的数值；
- 计算中位数、MAD（median absolute deviation）或相对离散度；
- 若至少两个独立源同向且数值接近、另一个源远离共识，标记离群源；
- 只有字段定义、时间、单位已对齐且离群证据充分，才排除离群源并采用低离散度共识；
- 若平台口径不可比、有效源不足或冲突无法解释，保留各源原值并输出“数据冲突/无法判定”，禁止强行生成“增持/减持”或“主力吸筹”结论。

注意：不能把“多数平台”作为唯一真理；平台独立性、字段映射和时间一致性必须先验证。新浪 Web 与新浪 App 视为两个不同产品。

### 4. 报告语义守卫

- 未形成跨源共识时，禁止写“主力增持”“主力吸筹”“洗盘”“即将拉升”；
- 资金流正负只表示特定平台/分类口径下的净额，不自动推出机构意图；
- 报告必须同时展示平台、字段、日期、单位、单日/累计窗口和离散度；
- 失败、缺失、不可比必须进入 evidence gap / data_gaps；
- 旧报告不可回填，修复后用新报告验证。

### 5. 定向验收对象

至少验证 `002167.SZ`：
- `2026-08-13` 单日；
- 近 5 个交易日；
- 新浪 Web、东方财富、同花顺/富耀、可获得的新浪 App 口径；
- 逐项对齐主力、特大单、大单、中单、小单、总净额；
- 明确哪些字段可比、哪些不可比；
- 解释为什么新浪 Web 与 App 不同，不能用 Web 自洽替代 App 证据。

### 6. 测试要求

新增或更新测试覆盖：
- 多源字段结构化保存；
- 单位与窗口一致性；
- 离散度/MAD计算；
- 离群源识别但不误删不可比源；
- 两源同向、一源反向时的共识/冲突分支；
- 跨平台主力冲突阻断方向性结论；
- 失败和缺少 endpoint 时显式 evidence gap；
- `r0_net` 不得自动标记为 App 主力；
- 正流入不得自动推断吸筹。

### 7. 交付纪律

- 先提交真实远端 branch/commit，再进入复审；
- 不得修改用户模型绑定、provider、API Key 或个人设置；
- 不得把凭据写入代码、评论、日志或测试 fixture；
- 必须提供 `.venv310` 定向测试、compileall、diff check 和真实 provider 探针结果；
- 复审/回归/合入/重启服务前，必须验证最新远端 SHA；
- 未完成跨源同日证据前，DAV-119 不得通过，后续质量门保持锁定。

## 已知阻塞

4. 冲突时报告方向性结论已被阻断。

因此不能宣称当前修复已完成或已上线。

## 舆情部分

雪球榜单必须保存 selector（`本周新增`/`最热门`）、排名、代码、名称、关注数、抓取时间和 `as_of`。历史日期没有可复现快照时不得具名列举热搜股票。舆情部分与资金流部分均遵循证据优先和不可比则标冲突规则。

## 验收口径

只有同时满足“多源同日原始证据 + 可比性判定 + 离散度/离群处理 + 冲突语义守卫 + 定向测试 + 真实探针 + 复审通过 + 合入上线 + 新报告复核”才算完成。否则保持在对应质量门，不得只凭模型报告或单一 Web 接口自洽结论收口。
