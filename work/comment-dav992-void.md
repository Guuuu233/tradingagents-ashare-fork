## 本卡作废：与 DAV-989 重复，且验收标准基于已撤销的错误根因

两点原因：

1. **重复**：DAV-989「窄修：修复 API lifespan 全局 executor/客户端资源泄漏」早于本卡创建，白名单完全相同（`api/main.py`、`tests/test_api_smoke.py`），且已交付候选 `b5f63d4ce55e67090214b1607287da615a10ee16`，复审卡 DAV-991 在办。**本卡是我建卡前未检索 DAV-979 既有子卡导致的重复投入，责任在运维侧。**
2. **验收标准错误**：本卡 AC-1/AC-2 建立在「根因是 lifespan 关闭模块级全局 `_executor`」这一判断上。该判断已被实测推翻——`b5f63d4` 正是按此方向修的，复现命令仍在同一位置卡住。真实原因是**测试在打真实外网**（baostock 裸 TCP，不受 `http_proxy` 约束），套件并非死锁而是极慢（实测 `api_smoke + fund_flow` = `67 passed in 1305.87s`，退出码 0）。完整证据见 DAV-979 的「重大更正」评论。

因此本卡按 AC 验收会把开发引向错误方向，予以 cancelled。真正要做的事已在 DAV-979 更正评论里列为四条建议（离线护栏、定位 api_smoke 全局状态污染、baostock socket 超时、测试环境超时下调），将另行立卡，不在本卡继续。

已完成的任何工作请不要丢弃，可转入 DAV-989 或后续新卡。
