# 第一部分：发现了什么

## 0. 起因与结论概述

起因是「刚跑的分析有些数据取不到了，感觉以前能取到」。逐层追查后，实际问题比「取不到」严重：

1. **报告被阉割**——但不是数据源挂了，是资金流守卫拦截导致下游四个章节全部短路。
2. **全球指数存在错误数据**——不只是缺失。已实证至少 5 份报告的外盘数值偏离真值 12%–31%，
   另有 11 份报告出现精确 100 倍的缩放错误，且全部标记为 `available/verified`。
3. **根因是架构层面的**——关键宏观数据只挂在一条免费网页抓取链上，而用户付费的 Tushare
   **根本不是一个 provider**，不参与任何 vendor 路由。

## 1. 报告「阉割」的真因：不是采集失败

对比三份报告的章节字节数（章节结构 10 节完全一致，无整节缺失）：

| 章节 | 002241（9/4跑） | 600519（9/18跑） | 600036（9/19跑） |
|---|---|---|---|
| 市场/舆情/新闻/基本面/宏观/量价 合计 | 24,903 | 24,442 | **24,707** |
| 主力资金报告 | 4,165 | 4,500 | **83** |
| 研究团队决策 | 3,555 | 4,380 | **99** |
| 交易团队计划 | 2,104 | 1,996 | **45** |
| 最终交易决策 | 4,031 | 3,250 | **116** |
| 总计 | 38,858 | 38,568 | 25,050 |

**前六个分析师一个没少，体量还略增**（新闻 4,628→5,503，量价 4,370→5,166）。
塌掉的四节内容全是同一句话：

> 资金流来源选择不可用或结构化累计存在冲突；已阻断增持、减持、吸筹方向摘要。

后续三节依次是「guard 已阻断，状态=ABSTAIN」「不得生成方向性交易计划」「风险计划不得批准方向」。

**结论**：缩水 38,858→25,050 全部来自资金流守卫拦截导致的下游短路，与数据采集无关。

## 3. 根因定位

> **本节定性说明**：以下 3.1–3.5 中，**代码缺陷本身已坐实**（缺新鲜度闸、无值域校验、
> 盘前美股日期函数不判收盘、路由顺序差异、完整性标记失真）。
> 但「日经跨四个基准日同值**就是由** `iloc[-1]` 取到陈旧行造成」属于
> **与观测一致的主要解释，尚未完成因果闭环**——需要实际 `actual_as_of` 取值或可复现 fixture 才能证实。
> 施工时按缺陷修，不要把该解释当成已证明的因果链引用。

### 3.1 已坐实（缺陷）：`calculate_series_metrics` 缺新鲜度闸

`tradingagents/dataflows/macro_market_utils.py:60,75`

```python
df_work = df_work[df_work["date"] <= end_dt]   # 只保证不超过基准日
...
last_row = df_work.iloc[-1]                     # 取序列最后一行
actual_as_of = last_row["date"].strftime("%Y-%m-%d")
```

过滤只保证**不超过**基准日，不保证**接近**基准日。若上游序列末尾停在某个早得多的日期，
则任意晚于该日期的基准日都会取到同一行。这与日经四个基准日同值的观测一致。

连带问题：`change_1d_pct` 用 `iloc[-1]` 与 `iloc[-2]` 之差，因此报出的「单日涨跌」
是陈旧行当天的涨跌，不是基准日的。日经 `-0.90%` 四次不变即此。

**渲染层的问题比「未渲染」更严重**（`macro_market_utils.py:193-196`）：

```python
valid_dates = [m["as_of"] for m in valid_items.values() ...]
actual_as_of = max(valid_dates) if valid_dates else requested_as_of
lines = [f"## 全球核心市场指数行情（数据基准日：{actual_as_of}…）",
         f"【数据日期】{actual_as_of}", ...]
```

`build_global_indices_markdown` **确实渲染了日期**，但渲染的是**所有指数 `as_of` 的最大值**，
并把它当作整表的「数据基准日」。因此只要有一项新鲜，整张表就顶着一个新鲜日期，
陈旧项被完全掩盖；表格逐行也不携带各自的实际日期。

这比「不渲染」危险——不渲染至少是空白，读者可能起疑；聚合最大日期是**主动给陈旧数据发合格证**。

**修复要求**：必须**逐指数**渲染各自的 `as_of` 与 `source`，聚合日期（若保留）
只能作为附加信息，不得单独作为全表基准日。

### 3.2 已坐实：`_get_latest_us_session_date()` 填当前时间且不判收盘

`cn_akshare_provider.py:674-701`

```python
if dt_or_ts is None:
    dt = datetime.now(ny_tz)     # 填「现在」
...
weekday = dt.weekday()
if weekday == 5: session_dt = dt - timedelta(days=1)   # 只回退周末
elif weekday == 6: session_dt = dt - timedelta(days=2)
else: session_dt = dt
```

只回退周末，**不判断当日美股盘是否已收**。实证：

- `d8ca6ffc` 跑于 9/8 13:36 CST = 01:36 EDT（未开盘），返回 `2026-09-08`，实际最近完成的是 9/7 盘。
- `6350b744` 跑于 9/10 19:34 CST = 07:34 EDT（未开盘），返回 `2026-09-10`，实际最近完成的是 9/9 盘。

两次都把快照**向前贴了一个交易日的标签**。

### 3.3 已坐实：无值域校验

`calculate_series_metrics` 只校验能否转成数字（`pd.to_numeric`）与不超过基准日，
**不校验数值对该标的是否可能**。标普 767,728 与标普 6,643 在代码眼里是同一类东西。

### 3.4 已坐实：同日 / 跨日路由差异

`cn_akshare_provider.py:7108`

```python
if is_historical:
    _fetch_from_hist(); _fetch_from_snapshots()   # 历史：先真历史，失败回退快照
else:
    _fetch_from_snapshots(); _fetch_from_hist()   # 当日：先实时快照
```

同日 / 跨日五样本零例外：

| 报告 | 基准日 | 跑于 | 同日 | 标普500 |
|---|---|---|---|---|
| `d8ca6ffc` 600519 | 09-08（周二） | 09-08 13:36 | 是 | 6643.70 |
| `6350b744` 600873 | 09-10（周四） | 09-10 19:34 | 是 | 6643.70 |
| `7ab31c86` 600519 | 09-08 | 09-09 04:39 | 否 | 缺失 |
| `b66f0b0b` 002241 | 08-24 | 09-04 09:47 | 否(+11天) | 缺失 |
| `31dcbebb` 600036 | 09-18 | 09-19 10:52 | 否 | 缺失 |

sina 的美股分支带 `is_historical` 守卫（`cn_akshare_provider.py:6909`），
历史日期下 `as_of = None`，因此跨日拿不到美股三大——**这是守卫在正常工作**，不是缺陷。

### 3.5 已坐实：完整性标记失真

部分成功被标为 `available/verified`，不记录「10 项中只成功 6 项」。
`data_collector.py` 从 Markdown 的「数据基准日」推断来源日期，不检查应有的指数集合；
质量闸主要检查是否出现「数据缺失」文本，不检查数量与数值合理性。
因此 19 条越界值与 6/10 部分成功都以 `verified` 身份进入下游。

# 第二部分：如何修

## 总原则

1. **换源与加闸必须在同一张卡内完成。** 换到 Tushare 能消除 100 倍缩放与陈旧值，
   但**不能替代**新鲜度闸与值域校验——100 倍成因未定位，兜底路径（akshare）仍可能复现。
   **不得先部署未加闸的换源版本**，否则兜底触发时问题原样重现且更难察觉。
2. **不得盲目除以 100。** 缩放成因未定位，适配器不得猜测并自动修正；
