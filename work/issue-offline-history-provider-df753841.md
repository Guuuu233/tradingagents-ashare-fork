# 离线测试历史案例链路消除外部等待

## 基线

- 固定代码基线：`df7538413ba7bb55593b1757feaf90b0bd514d1c`
- 目标是修测试隔离和确定性，不改变生产业务语义。
- 当前已知问题：报告完成后的历史案例记录会进入 provider 路由；在测试会话中可能等待裸 TCP 行情供应商，造成分钟级甚至更久的假死观感。

## 允许范围

- 优先只改测试 fixture、mock/依赖注入和测试辅助代码。
- 如确需产品代码增加测试 seam，必须保持默认生产行为不变，并在交付报告中单独列出；不得顺手改供应商语义、重试策略或生产超时。
- 不改 `pyproject` 把这些测试标成跳过网络，不删场景，不放宽断言，不屏蔽失败。

## 验收标准

1. 复现并记录修改前的慢路径，说明触发链路。
2. 相关离线测试在默认 offline guard 下不再尝试外部行情连接；应使用确定性的本地桩或显式 mock。
3. `test_fund_flow_scale_consumption`、`test_fund_flow_scale_metrics` 及受影响的历史案例/报告持久化测试定点通过。
4. 通过 socket guard、PEP 578、`curl_cffi` 等现有护栏验证没有隐藏外连。
5. 运行最小必要回归并报告精确计数；不得宣称因此修复了全部 RT-FULL 问题。
6. 不碰生产库、不部署、不重启服务。

## 交付规则

交付时必须给出候选完整 SHA、直接父、改动文件白名单、精确测试命令与结果、前后耗时和是否存在外部连接尝试。交付后只派 `代码审核员` 或 `代码审核员2` 做同 SHA 只读审查，不得自审。
