## 🔴 基础设施缺陷：vendor 连接不挂断（DAV-979 家族）

**根因**（三次错误归因后定案）：`site-packages/baostock/util/socketutil.py:55 send_msg`
```python
while True:
    recv = default_socket.recv(8192)       # 对端关闭后恒返回 b""
    receive += recv                         # 永不变化
    if receive[-13:] == b"<![CDATA[]]>\n":  # 永不匹配
        break
```
无 EOF 检查、无超时。**网络是通的**（同代理环境 `baostock.login()` 0.077s 成功、查行情 0.681s 成功，Clash 对 `public-api.baostock.com` 走 DIRECT）。问题是对方挂电话后旧客户端不挂断。

**两个形态完全相反的变体，必须都认识**：

| 形态 | %CPU | 例证 |
|---|---|---|
| 忙循环 | **≈100-132%** | PID 12371 空转 4h28m；PID 6619 132% 卡 1h19m；假 socket 复现 1 秒空转 433 万次 |
| 阻塞 | **≈0%** | PID 28304 卡 30min，CLOSE_WAIT on :https |

**CLOSE_WAIT 才是确诊依据，不是 CPU**（只看 CPU 会漏判 0% 那种）。检测脚本已落盘：`bash work/check-stuck-tests.sh`

**线程池 `future.result(timeout=)` 只能停止等待、杀不掉已运行的供应商线程**，故上层 60s 超时对此完全无效。

**触发链**：`POST /v1/reports` 存 completed 报告 → 历史案例计算 → baostock 取 T+1 行情 → 对端关闭 → 卡住。

**耗时构成**（正常网络下）：`--durations` 前 7 名全在 `test_fund_flow_scale_consumption.py`，每条 ≈181.3s ≈ 60s×3，合计约 21 分钟，占 28 分钟全程大头。**慢 ≠ 卡死**，基线是跑完了的。
