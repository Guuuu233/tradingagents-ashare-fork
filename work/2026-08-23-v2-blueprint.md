## 0. 三条设计公理(全部来自实测教训)

1. **分歧靠结构,不靠模型自觉。** 同模型自我辩论在相同输入下必然收敛为 2v2 拉锯(实测:34 条 claim 只在 6 个战场,第三轮逐字克隆证据);多模型回归后,差异也必须落在结构预留的空位上(双盲、战场制),否则被胜负制协议重新锁死。
2. **纪律靠闸门,不靠模型自觉。** 三道硬闸(辩论协议闸/证据采纳闸/裁决自洽闸)在三轮中拦截了 6 次 LLM 越界(5 次协议违规 + 1 次总监正文造假未遂),拦截率 100%。这是系统最硬的资产,新架构只加闸不减闸。
3. **信任靠校准,不靠辞藻。** 600276 证明总监会被修辞带偏(把 coverage 50% 的 claim 写成"证据充分"),靠自洽闸才兜住。长期信任必须建立在辩手/总监/分析师的事后命中率与信用分上,且对用户透明可见。

## 2. 目标架构:五层流水线

```
L1 数据层(战场导向)     → 按五战场供弹,死源退役,代理指标补位
L2 分析师层(七报告)     → 基本保留,输出增加战场标签
L3 对抗层(三段式)       → 双盲立论 → 单轮交叉盘问 → (可选加赛一轮)
L4 裁决层              → 分歧地图 + 证据闸 + 自洽闸 + 击穿盘问
L5 校准层              → 信用分 × historical_cases × calibration 闭环,用户可见
横切:评测基础设施(金标准/A-B 实验/自动化指标看板)——一等公民,不是附属
```

## 3. 分项设计

### F1 对抗层重构:三段式协议(核心工程)

**现状问题(证据):** `zh.py:196/248` 强制"第 2-6 次发言每条 new_claim 必须指向对手 claim"+ R3"聚焦核心分歧"→ 议题广度锁死在 R1 的每方 1-2 个 claim;`debate_utils.py:868-885` 捆绑漏洞让克隆 claim 随一条改写证据洗白(000333 INV-9 证据相似度 0.986/1.0 仍入库)。

**改成什么:**

**与 `max_debate_rounds=3` 的映射(产品配置不变,协议语义变):**
- 第 1 轮 = 第一段双盲立论(多空各 1 次发言,互不可见)
- 第 2 轮 = 第二段交叉盘问(多空各 1 次,禁重申/禁新增己方 claim)
- 第 3 轮 = 可选定向加赛(总监触发才跑;未触发则该轮跳过并在 result_data 标明 `tiebreak_skipped=true`,**不得**改用户 3/1 配置去“省一轮”)

**第一段·双盲完整立论(占 max_debate_rounds 的第 1 轮)**
- 语义要求是**互不可见**,不是必须同时执行。
- **Phase 1 首选(免改拓扑):** 图保持现有串行乒乓;researcher 按 `stage=opening` 构造 prompt 时 `history`/`current_response` 置空、claims/focus/unresolved 只含己方(立论时为零)、`past_memory` 对本 ticker `n_matches=0`。Bull 仍先于 Bear 执行,Bear 只是看不到对方立论;claim 编号走共享计数器,顺序执行不冲突。
- **硬约束(漏则伪双盲/直接 invalid_protocol):** Check B/C 目前是 `if message_index >= 2`(`debate_utils.py:768/798`)。顺序图上空头立论是第 2 次发言,若不改闸,空头 R1 会被强制要求回应并 target 对手 claim——双盲立论当场拒收。必须把 B/C 改为**按 stage 分相**:`opening` 即使 `message_index=2` 也走立论契约(target/responded 为空);`challenge` 才强制反驳且 `new_claims` 必须空。`stage` 必须进 payload/state,禁止只改 prompt 不改闸。
- **fan-out+join 并行立论**留作延迟优化另卡,不是双盲的语义必要条件。
- 每方输出 2-3 条完整立论 claim(带证据、置信度、失效条件),**必须覆盖 A 股五战场中总监圈定的 ≥3 个**(见 F2),不适用战场须显式写"不适用+原因"。
- 多模型差异性的部署位置:多空用不同模型(同档)——**仅当用户已自行把两角色绑到同档异模时启用**;默认保持用户当前绑定,系统不代换。

**第二段·单轮交叉盘问(占第 2 轮,方向与现行反驳制相反)**
- 每方一条,输入=对方全部立论+己方立论。
- **只许指出对方论证最脆弱处并给数据,禁止重申己方立场、禁止新增己方 claim**(校验:`new_claims` 必须为空数组,否则 invalid_protocol——复用现有协议闸)。
- 输出固定结构(challenge 对象,新增):
  ```json
  {"target_claim_id": "INV-3", "weakest_point": "将散户调仓误读为主力出逃",
   "evidence": ["中单-1.19亿/小单-0.81亿 vs 超大单+1.29亿"], "severity": "fatal|major|minor"}
  ```
- 理论依据:交叉盘问是辩论唯一不可替代的功能——600900 资金口径二阶分解(全辩论最有含金量的分析)正是被空头直拳逼出来的;而"只挑最弱处+禁重申"从结构上杀死回收克隆的动机。

**可选第三段·定向加赛(限一次)**
- 仅当总监发现"相同数据、解读相反"且证据闸无法裁决时触发,追加一轮定向澄清问(只答一个问题),杜绝无限拉锯。

**涉及文件:** `zh.py`(bull/bear_prompt 三段式重写 + **research_manager_prompt 轮次参数化**,现文写死"基于3轮辩论严格执行")、`bull_researcher.py`/`bear_researcher.py`(按 stage 构造输入;opening 不注入对方 history)、`debate_utils.py`(Check B/C 改为按 stage 分相;新增 challenge 校验闸;废除捆绑放行——per-claim 判重后重复 claim 拒收入库)、`conditional_logic.py`(第3轮可跳过路由+`tiebreak_skipped`;Phase 1 **不改** setup.py 拓扑)、`research_manager.py`(challenge 证据走 `EvidenceFactualTruthEvaluator`,与 claim 同一闸)、前端 `HistoricalDebateDrawer.tsx` + types(见下)。

**Phase 1 施工卡必须钉死的实现缺口(漏一项即拒收):**
1. **总监 prompt 轮次参数化。** `zh.py` research_manager_prompt 写死"五步深度裁决框架(基于3轮辩论严格执行)"。R3 跳过后若不按实际 `count`/`tiebreak_skipped` 注入,总监会对着不存在的一轮裁决,或自洽闸误判。
2. **双盲=输入隔离+闸门分相,禁止伪双盲。** 仅"prompt 里不填 history 字符串"不够。顺序图必须:(a) opening 段 prompt 六个输入收敛(history/current_response 空、claims 只己方、past_memory n_matches=0);(b) Check B/C 按 stage 而非 `message_index>=2`,否则空头第 2 次发言被强制反驳。fan-out/join 不是本卡范围。
3. **前端辩论查看器不得沉默断层。** `HistoricalDebateDrawer.tsx`(DAV-335)按 `round_messages` 渲染;既有测试假定 6 条消息。三段式是 4 条(+可选 2 条)+ `challenges[]` + `tiebreak_skipped`。Phase 1 **必须含前端适配**,或在卡上显式声明"查看器 v2 另开 DAV-xxx"并保证旧抽屉不崩。
4. **challenge.evidence[] 必须过核验闸。** 现网 `research_manager.py` 只对 `claims` 调 `evaluate_claims`。fatal 未 verified 不得否决 claim。依赖 C 泳道多行聚合已合入主干。

**验收标准:**
- 数据利用率(七报告数字进辩论比例)≥70%,宏观/基本面各 ≥50%(现状 48-53%/20-30%);
- 证据回收克隆零发生(数字级判重,不是字符串级);
- 每场辩论 challenge ≥2 条且总监对被 challenge 的 claim 逐条显式裁决;
- A/B:**离线**金标准回放可同三只审计标的对比现行制 vs 三段式; **上线验收换全新标的**(与防过拟合纪律一致);
- 库内用户配置验收后仍为辩论 3 / 风险 1。

### F2 战场制议程(A 股五战场)

**改成什么:** 辩论战场固化为五个 A 股定价维度,总监开战前按当期相关性圈定:
1. 资金筹码(主力分单/两融/回购/大宗/解禁)——A 股短线第一战场
2. 情绪题材(连板高度/涨停生态/风格轮动)——**本系统已有的差异化优势**,sentiment 报告的涨停生态数据是真实团队的散户情绪代理,升格为正式战场
3. 量价技术(支撑阻力/量比/威科夫阶段)
4. 政策与宏观流动性(利率/财政/行业政策传导时滞)
5. 基本面与财报兑现(业绩/应收毛利/财报日历风险)

**涉及文件:** `research_manager_prompt`(开战圈定+分歧地图输出)、`zh.py`(立论覆盖要求)、round_goal 生成逻辑。

**验收:** 每份报告的辩论至少覆盖 3 战场;连续 10 轮监控战场分布无单点聚集。

### F3 裁决层增强

**改成什么(在现有五步裁决上加三样,不动证据闸/自洽闸):**
1. **分歧地图**:裁决第一输出节=列出"数据相同、解读相反"的点(如同一笔流出,一方派发一方洗盘),逐条裁决**数据解读**而非立场宣言——桥水式收敛。
2. **击穿盘问**:每轮核对双方上轮宣布的失效条件是否被新数据触发;触发即强制降置信,不允许口头硬扛。系统已有 `falsification_conditions` 字段,只差"被触发后强制执行"。
3. **challenge 裁决**:对第二段每条 challenge 显式裁决(采纳/驳回+理由);仅当该 challenge 的 `evidence[]` 经 `evidence_verifier` 为 verified(或无数字的定性证据过关键词闸)后,被采纳的 fatal 才可否决对应 claim。unsupported/contradicted 的 challenge 不得作为否决依据,记入 `excluded_evidence`。

**验收:** 分歧地图非空;600276 式"极端推演喊 40 元但失效条件从不核对"脱节消失;总监自洽闸触发率趋零(理想)或触发即拦截。

### F4 信念轨迹与退化检测

**改成什么:** 每段结束双方提交 `self_win_prob`(0-1);总监监测:三轮全段双方概率纹丝不动 → `debate_degenerate=true`,跳过表演性收尾直接按证据裁决(Tetlock:信念从不更新=过程失败信号)。
**验收:** 退化辩论能被标记;标记后总监裁决仍经证据闸。

### G1 多模型编排与偏置防护

**现状:** role_bindings 已支持逐角色模型分配(机制已在)。用户当前全角色绑定由用户自行维护。
**改成什么(只建议、不代改绑定):**
- 文档建议多空**同档异模**;配置校验器在启动时若检测到跨档(强模多头+弱模空头)则 **warn**,不得自动改绑、不得静默轮换用户模型;
- 若用户**自己**配置了跨档,系统可在报告元数据记录 `模型×方向`,≥10 轮后检测偏置(|verified 率差|>10pt 告警)——检测与告警可以做,换模必须用户动手;
- 严禁助手/施工卡去改 `user_llm_configs` / role_bindings / providers / API Key。

**验收:** 多模型轮换 10 轮后,多空 verified 率差、胜率差均 <10pt;单模型与多模型 A/B 对比数据利用率与裁决质量。

### G2 数据层按战场价值重构(与 hermes 泳道 A 协同)

**改成什么:**
- **退役**(显式 known-gap,不再每轮刷"获取失败"):北向明细(2024-08 起披露停止→改用 ETF 份额变动+两融净买入作机构动向代理,数据活着且 A 股有效);板块即时快照(仅当日,历史分析移除)。
- **优先修**(战场价值排序):fund_flow_individual(个股资金流历史——第一战场的弹药,当前"未返回可验证数据日期")、share_pledge(A 股特有风险因子)、8 项报表 as-of(hermes A 泳道)。
- **红线**(AGENTS.md 3.5 已有前科记录):禁止用放宽 as-of 验证或填默认日期来"消灭缺口"。
**验收:** data_gaps 常驻 ≤5 项;资金筹码战场证据 verified 率不再因源缺失被拉低。

### H1 校准闭环:辩手/总监/分析师信用分(轻量版可信度加权)

拆成两期,禁止"三个月后再说采集":
- **H1a 影子采集(随 F1 或紧随 F1,零加权):** 每份报告只读计算并落库——辩手 verified 率、challenge 采纳率、T+5 方向命中(窗口到了才填)。数据来自已有 `claim_evidence_summary` / `historical_cases` / `evidence_verification`,不进总监采纳公式、不改裁决。现在不采,三个月后激活仍无样本。
- **H1b 加权激活(闸门=样本量≥N 且多空信用分差<10pt):** 总监采纳 claim 时按辩手信用分加权;信用分对用户可见。

**改成什么(H1b 才启用加权):**
- **辩手分** = α·claim verified 率 + β·方向命中率(T+5 事后)+ γ·challenge 采纳率,跨报告累计;
- **总监分** = 裁决方向与事后一致率 + 自洽闸触发率(低=好)+ 证据引用覆盖率;
- **分析师分** = 报告数据被辩论/裁决的利用率 + 关键数据 verified 率。

**涉及:** 新表或 JSON 字段 `agent_credit_scores`(H1a 即可建表只写不读进裁决);historical_cases 回填调度;前端报告页信用分卡片(H1b)。
**验收 H1a:** 新报告落库即有影子分,加权字段恒为关闭。**验收 H1b:** 样本量达标后信用分分化可见;多空差 <10pt;校准曲线前端可见。

### H2 评测基础设施(一等公民)

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 多模型引入新偏置(能力差≠立场差) | 同档异模、跨档轮换、模型×方向偏置监控(见 G1) |
| 三段式削弱"对抗强度"表象 | 以指标为准:challenge 采纳率、利用率,不以修辞强度为准 |
| 协议大改导致 prompt 工程回归 | 金标准+A/B 框架先行(Phase 1 前先建实验底座);分批合入 |
| 校准样本积累慢(周级) | 提高定时评测频率;historical_cases 回填历史报告 |
| 对三只审计标的过拟合 | 防过拟合纪律:验收一律换新标的,金标准只做回归不做调参 |

## 6. 明确不做的(边界)

1. 不做多模型**跨档**对抗(成本+偏置双输);也不自动改用户角色绑定;
2. 不做盘中实时辩论(盘后 T+1 决策是合理形态);
3. 不做无限轮加赛(退化即早收,不加表演);第 3 轮加赛未触发时跳过并记账,不改用户 3/1 配置;
4. 不用放宽闸门换指标(三道硬闸只加不减);
5. 不追求"辩论观赏性"(一切以可测量指标裁决好坏);
6. 不把金标准三只标的当调参对象;不把"字段不存在"的审计 dump 当 DB 证据(R0)。
