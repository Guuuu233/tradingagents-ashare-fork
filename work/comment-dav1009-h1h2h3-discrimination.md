## 判别口径修正：补入 H3，并给出正式判定表

**本条是取证口径修正，不是实施授权。** 生产代码继续保持零改动。

---

### 一、H1/H2 的互斥性是有边界的

我上一条把 H1/H2 当成二选一，**说窄了**。它们只在 **「同一个 socket、同一次连接尝试」** 这个粒度上互斥；**放到整个进程层面并不完备**。

### 二、补入 H3

> **H3**：某次 `connect` 被护栏拒绝并记录，但**卡住的 `recv` 用的是另一个线程、另一条连接，或此前遗留的全局 socket**。

它之所以可能，正是 baostock 的结构决定的：

```
context.default_socket     模块级全局
SocketUtil.instance        单例
max_concurrency = 2        provider 并发上限 2
```

**在 H3 下，deny 记录与 ESTABLISHED 连接可以同时出现而毫不矛盾**——一条被拒、另一条活着。所以「看到 deny 就判 H2」「看到 ESTABLISHED 就判 H1」都是错的。

### 三、判别必须做关联，而非各看各的

单看任一条日志都不足以定性。必须把以下维度**关联到同一对象**：

| 维度 | 要求 |
|---|---|
| PID | 同一进程 |
| nodeid | 同一用例 |
| 时间窗口 | 同一次复现的同一时刻 |
| observer / deny | 是否**成对**出现 |
| socket 对象或 fd | 能否对应到**同一个** socket |
| lsof | 对应 **fd / 目标端口** |
| 原生栈 | **阻塞线程**是哪一个 |

### 四、正式判定表

| 证据组合 | 判定 |
|---|---|
| 有**配对** deny、**无**对应 ESTABLISHED、随后**快速返回** | **H2** |
| observer 有记录但**无** deny，且**同一连接** ESTABLISHED、栈**阻塞在 recv** | **H1 → 返回卡 A** |
| deny 与 ESTABLISHED/recv **同时存在但无法对应同一 socket** | **不能二选一**，继续查多连接或旧全局状态 |

第三行是新增的诚实出口：**证据不足时必须停在「未判定」，不许强行二选一凑结论**。

### 五、卡 B 不作废，只是暂停

修正上一条的口径。即便最终判定为 H1，以下仍是**独立的生产缺陷**，不因 H1 而消失：

1. `socketutil.py:39` **宽泛吞错**（`except Exception` 吞掉一切，只 print）
2. `socketutil.py:41` **连接失败后仍把 socket 写入全局**
3. **全包 0 处 `settimeout`** → 无限阻塞
4. `send_msg` 的 `recv` 循环（`:67-73`）**无 EOF 判断**

所以：**卡 B 保留，状态改为暂停**；若判定 H1，**先修卡 A 的隔离漏洞**，卡 B 随后再排期。
