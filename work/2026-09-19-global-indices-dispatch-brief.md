## 4. 这个任务特有的坑（按危害排序）

### 坑 1：`VendorRefuse` 语义极易写反（会造成新回归）

实测 `interface.py:554-568`：

```python
if isinstance(result, VendorRefuse):
    if result.allow_peers:
        peer_allowlist = set(result.allow_peers); break   # 带 peers → 链路继续
    return result.to_prompt()                              # 裸 refuse → 链路终止
```

**裸 `VendorRefuse` 终止整条链，不回退。** 新 provider 若不实现 `get_major_assets`，
正确做法三选一：不定义该方法让路由跳过（推荐）／抛 `NotImplementedError` 或返回
`VendorFail`／确需 refuse 必须带 `allow_peers=("cn_akshare",)`。

写反的后果：`macro_market_data` 链切换后，`get_major_assets`
（黄金/原油/美元指数/美债10年/LME铜）被一枪打死，且是**新引入的回归**。
审查时专门核这一点。

### 坑 2：值域校验必须在知道标的身份的那一层做

通用的 `calculate_series_metrics()` 只拿到裸 DataFrame，**不知道 `767728` 属于标普**，
无法自行判断 100 倍异常。二选一：适配器按 `SPX` 等标的契约校验，或给通用函数传入
instrument contract。**不得只写一个裸数字的测试**（G1 已要求带 `ts_code`）。

### 坑 3：断言不得依赖点位数值

两个交易日的指数收盘**合法地可能相同**，不能用「两个日期点位必须不同」证明无陈旧数据。
判定陈旧必须依据 `actual_as_of` 与新鲜度阈值。若要比较点位，用人为构造的
不同日期不同值 fixture（G8）。

### 坑 4：渲染层是「聚合最大值」不是「未渲染」

`macro_market_utils.py:193-196` 取 `max(valid_dates)` 当全表「数据基准日」。
只要有一项新鲜，整表就顶着新鲜日期，陈旧项被掩盖。修复要求是**逐指数**渲染
各自 `as_of` 与 `source`，不是「补上渲染」。

### 坑 5：通用函数有多个调用方

`calculate_series_metrics` 被 `get_major_assets` 等多处共用，加新鲜度闸会影响所有调用方。
**施工前必须 grep 全部调用点并逐个评估阈值适用性**，境外指数与大宗商品/美债的
合理新鲜度窗口可能不同。

### 坑 6：换源不得先于加闸部署

100 倍成因未定位，akshare 兜底路径仍可能复现。**不得先部署未加闸的换源版本**，
否则兜底触发时问题原样重现且更难察觉。两者必须同卡完成。
