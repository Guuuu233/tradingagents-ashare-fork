## 目标
修复 A 股股票名映射缓存"加载失败即冻结 7 天"的问题：东财（akshare）临时限流导致加载失败时，应短时间后自动重试，而不是让中文名消失一周。

## 背景（Hermes 实测，2026-08-06）
- 现象：服务 14:53 启动时东财被限流，`_load_cn_stock_map()`（api/main.py:439）失败 → `_cn_stock_map = {}`（空 dict 写入全局，第 493-495 行）→ 之后 7 天内所有报告列表/搜索的中文名全部消失（`_get_reverse_stock_map_cached_only()` 返回空 → 前端只显示股票代码）
- 根因：失败路径把"空结果"当成"合法缓存"存下，且 TTL 7 天（`_STOCK_MAP_TTL = 7 * 86400`，第 436 行）内不重试
- 用户影响：东财限流（本月已发生多次）期间，历史报告栏、定时任务列表等所有依赖 stock map 的界面集体丢失中文名

## 修复要求
1. **失败后快速重试**：加载失败时不写"空缓存"，或写入"失败时间戳"并允许在短间隔（建议 30 分钟，可配置）后重试；加载成功后才启动 7 天 TTL
2. **保持幂等与并发安全**：现有 `_cn_stock_map_lock` 语义保持；多请求并发时只触发一次真实加载（现状已是双重检查，勿破坏）
3. **失败有日志**：`[StockMap] Failed to load` 已存在，补充"将在 X 分钟后重试"信息
4. **不改动**：`_get_reverse_stock_map_cached_only` 的"冷缓存快速返回空"行为（列表页响应速度优先）保持；`_get_reverse_stock_map`/`_search_cn_stock_by_name` 的显式加载行为保持
5. 需要检查是否存在其他类似"失败冻结"的缓存模式（如 `_cn_stock_map_norm`），一并处理或说明

## 测试要求（TDD）
- mock akshare 首次抛异常 → `_load_cn_stock_map()` 返回空且不冻结（后续调用立即重试而非等待 7 天）
- mock akshare 先失败后成功 → 第二次调用加载成功并填充 reverse map
- mock akshare 成功 → 正常缓存 7 天 TTL 行为不回归
- 并发下只加载一次（现有行为不回归）
- 全量回归 0 新增失败

## 验收标准
- 加载失败后 30 分钟（或配置值）内自动重试成功，中文名恢复
- 现有测试全绿；全量回归 0 新增失败
