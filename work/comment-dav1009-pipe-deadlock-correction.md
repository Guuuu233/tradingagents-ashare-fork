## 更正：那 21 分钟阻塞是「诊断执行的管道死锁」，不是产品的 45 秒问题

**本条是返修派工。** 卡 B 第一阶段**尚未完成**。

### 定性

`pytest tests/test_api_smoke.py -vv -s`（PID 30676）阻塞 21 分钟、CPU 0.0%、无网络 fd。主控已复核，进程与父 shell 均已结束，无残留。

```
30676  fd 1u  unix 0xdecc54c33c03b595 -> 0x80c084e5e099b28f
30676  fd 2u  unix 0xe8fc90a24373bed5 -> 0xc389f484ff84f225
对端: PID 28000 ← 19395 (pi harness)
```

stdout/stderr 是通往 harness 的 **unix socket**。`-vv -s` 产出海量输出把 socket 缓冲写满，对端不再读取 → pytest **阻塞在 `write()`**。

这是**诊断执行环境的管道死锁**，与产品的 45 秒等待**不是同一个问题**。
⚠️ **该次输出不得作为产品诊断证据。**

### 主控对照实验（三次，均输出重定向到文件）

同一工作树、同一 DB、同一命令：

| 配置 | 结果 |
|---|---|
| `-q -p no:randomly` | **55 passed in 7.54s** |
| 随机顺序 | **55 passed in 7.93s** |
| 原样复刻 `-vv -s` | **55 passed in 7.87s** |

**结论：`tests/test_api_smoke.py` 单跑不会触发 45 秒停顿。**

同时已排除：测试顺序、DB 数据差异（两边同为 `/private/tmp/multica-task-.../pytest.db`，15 reports / 4 historical_cases）、yfinance 陈旧锁（缓存目录无 lock 文件）。

### 四条更正

**1. 禁止 pytest 大量输出直连无人持续读取的 harness socket。**
stdout/stderr **一律重定向到仓库外唯一文件**（如 `> /tmp/dav1009_<tag>.log 2>&1`），再去读文件。

**2. 撤销「必须用单文件/单用例复现」的要求。**
该要求已被证伪——45 秒只在**全量上下文**中出现，依赖前序上千用例累积的进程内状态。
改为：复现**包含必要前序状态的最小切片**；暂时找不到最小切片时，允许**按原顺序运行到首次 45 秒停顿即停止取证**，不必跑完。

**3. 必须加 `-o faulthandler_timeout=25`。**
pytest 自带，无需 root、无需装包，单个用例超时会自动 dump**所有线程栈**。
你上一条命令没带它，**跑完也拿不到任何栈**。
（`py-spy` 在 macOS 需要 root，此路不通，不要再试。）

**4. 在拿到全量上下文中的真实栈 + 时间线之前，禁止修改生产代码。**
